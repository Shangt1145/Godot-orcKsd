# 6B1：卡池准入审核与安全组牌

日期：2026-10-07。阶段完成，版本 `0.0.0-alpha.12`。本阶段为 6B 的第一个子阶段；没有完成效果 DSL 转换，也不宣称全卡池语义兼容。

## 计划与完成条件

1. 区分结构可映射、完整支持、未审核、生成卡和不支持，并为每张卡提供原因。
2. 真实对局只接受源声明经审核的卡；源声明变更或 UI 定义偏离源数据时停止准入。
3. 组牌过滤生成卡，满足明确的张数、最多三份同名卡及最低八张单位；容量不足报错，不返回短牌组。
4. 用真实引擎核验每张审核卡的装载、部署、扣费、攻防与操作费用；用 Godot 鼠标入口核验生产对局。
5. 完整回归通过后提交并推送项目代码。引擎不拉取、不修改。

## 实现与支持范围

`VerifiedCardPool` 在桥接导入层读取原始 JSON，检查效果声明、完整数值、兵种、生成卡标记及已审核清单。原始效果不进入 UI DTO。审核清单作为桥接嵌入资源保存，每张声明绑定 SHA-256；完整声明变化需要重新审核。UI 数据也必须与读取到的源数据一致。

| 卡 ID | 已审核内容 |
|---|---|
| av76/units/12 | 轰炸机基础数值 |
| av76/units/13 | 战斗机基础数值 |
| av76/units/15 | 轰炸机数值、闪击 |
| av76/units/16 | 步兵数值、烟幕、动员 |
| av76/units/18 | 坦克数值、重甲 1；重复词条归并 |
| deran/units/_14 | 坦克数值、闪击 |
| deran/units/_4 | 坦克基础数值 |
| deran/units/_6q | 步兵基础数值 |
| USG/units/_4 | 坦克基础数值 |

这些卡采用当前引擎的国籍及词条映射；不等同于原版 KARDS 全部规则。稀有度仍遵循既有映射策略，无法对应的来源稀有度使用 Standard。本阶段未新增效果处理器。

源数据 315 张：结构可映射 150 张；审核支持 9 张；仅生成 84 张；不支持 222 张。分类按生成卡优先，不能把结构覆盖数视作完整支持数。`USG/units/_1` 与 `_2` 缺少操作费用，明确拒绝，没有填零；自定义兵种没有静默删除；非空、缺失或畸形 effects 声明均不当作无效果卡。

9 种卡最多可提供 27 份，不能填满正常的 30 张策略。因此真实入口暂用明确标注的 **24 张验证牌组**，由经审核定义确定性抽样生成；不强制指令，也不按低费加权。正常 `DeckRules.DeckSize=30` 保留，对审核池请求 30 张会报容量不足。此规模是验证支持集的项目配置，并非原版 KARDS 组牌规则。

`CardPoolCompiler.Compile` 继续用于结构诊断与旧投影夹具；生产工厂改走 `VerifiedCardPool`。初始化失败显示错误，不静默替换成探针；固定起手也必须来自审核支持集。通用引擎生命周期验证与生产卡池鼠标验证分别执行，避免以探针冒充真实卡池验收。
