## P7 收口了什么

**新增**

- `proto/core/RoomSettings.cs` —— 房主侧本地设置：房间名、是否固定端口、端口号。
  与卡库/卡组同口径（`SchemaVersioning` + 原子写 + 读失败保留原文件）。
- `proto/ui/screens/Main.RoomSettingsVerification.cs` —— `--verify-room-settings` 探针。
- `tests/RoomSettingsTests.cs` —— 15 条纯逻辑用例。

**改的是已有文件**

- `RoomScreen.cs`：房间设置面板（仅房主可见）；`ApplyRoomName` 一处同时管"写设置/通知宣告器/落盘"；
  固定端口失败退回自动分配并提示；`ConnectWithRetryAsync`（3 次退避）+ `DescribeJoinFailure`
  （socket 错误翻人话）+「重试加入」；「入场申请」→「房间成员」（待处理申请 + 已连接 + 移除，
  移除走 `conn.revoke`，就地二次确认）；`_needsReapply` 修掉"按钮永不出现"的重连死路。
- `RoomDiscovery.cs`：`RoomAnnouncer.Name` 可改 + `Rename`，改名不必重开房间。
- `Main.cs`：`FeedRestored` → `ResumeRemoteMatchAfterReconnect`，房主掉线重连后战场不再冻结。
- `ServerLauncher.cs`：`port` 参数一路带到 `ServerOptions.Port` / `SpawnRequest.Port`。

**为什么没有密码 / 观战延迟**（别当成漏做）

- 密码：`SessionAttachParams` 没有口令字段，服务端无从校验；客户端自校验＝假安全。
  现有的门是"房主逐条批准"，比口令更严。
- 观战延迟：不绑座 viewer 是**全知**（能看到双方手牌），延迟只把泄牌推后几十秒，挡不住。
  真修法是限制观战视角，属引擎侧角色设计。

`tools/run.ps1 -Capture` 会把面板三个页签和"面板没开时的倒计时"各拍一张（`artifacts/battle-log-*.png`）。

- 战报条目按时间顺序直排，没有按回合分组——条目多了以后想找"第 5 回合"只能靠肉眼。

| 命令 | 用途 | 耗时 |
|---|---|---|
| `tools/run.ps1 -Test` | 全量单测 | ~2 分钟 |
| `tools/run.ps1 -Verify` | 整轮 UI 探针（含战报面板、卡组断链/重新绑定） | ~7 分钟 |
| `tools/run.ps1 -VerifyRoomSettings` | 房间名/固定端口/房间成员（P7 新增开关） | ~1 分钟 |
| `tools/run.ps1 -VerifyDiscard` | 弃牌演出 + 弃牌堆（P6 新增开关） | ~1 分钟 |
| `tools/run.ps1 -VerifyDecks` | 卡组构筑全流程（P5 新增开关） | ~30 秒 |
| `tools/run.ps1 -VerifyCombat` | **真引擎**打完整一局（`COMBAT_VERIFY_OK`） | ~4 分钟 |
| `tools/run.ps1 -VerifyDiy` / `-VerifyAuthoring` | DIY / 检查器 | 各 ~30 秒 |
| `tools/run.ps1 -Capture` | 出图（含 `battle-log-{clock,0,1,2}.png`） | ~1.5 分钟 |

**坑 1**：必须走 `run.ps1`，它先设 `ORC_ENGINE_ROOT` / `ORC_SERVER_DLL`。
直接 `dotnet test` 会有 7 条 `NetworkWorkshopTests` 因找不到 `Orc.Server.dll` 变红（环境问题，不是代码问题）。

**坑 2**：`-VerifyNavigation` 与"源码刚改过后的第一次"任何探针，都会先做一段**静默的资源导入**。
本轮实测：同一段导入，直接对构建目录跑 45 秒完成；但**被 `run.ps1` 以 `*> 日志文件` 重定向的方式拉起时会挂死**
（`Godot_v4.7-stable_mono_win64_console.exe` 停在 CPU 0.33 秒、11 MB、无子进程，10 分钟不动）。
判据是"CPU 时间几乎不涨且没有子进程"；这种挂法杀掉重跑即可，第二次因为导入已热通常就过了。
**先看有没有子进程再决定杀不杀**，别把正常导入当卡死。

**坑 3**：探针日志是 UTF-16LE。读之前 `iconv -f UTF-16LE -t UTF-8`，否则中文全是乱码，grep 也匹配不到。

**坑 4**：`-VerifyDeck`（单数）是房间/卡组接线那条探针，**不是**卡组构筑全流程；后者是 `-VerifyDecks`（复数）。
`-VerifyCombat` 跑的是**真引擎整局**，不跑 `BATTLE_STAGE2`；`BattleScreen` 那套断言只在整轮 `-Verify` 里。

**坑 5**：运行副本的 `obj/` 是增量缓存，偶尔坚持一个源里已经不存在的错误。本轮实测：源里刚给
`BattleLog` 加 `Observe`，副本增量编译仍报 `CS1061`，紧接着 `-t:Rebuild` 立刻通过（两边文件字节一致）。
`run.ps1` 现在会自动全量重建重试一次；但**手工在副本里编译**时要记得 `-t:Rebuild`。

**坑 6**：`run.ps1` 的探针分支在 `$ErrorActionPreference = 'Continue'` 下跑，成败只看退出码。
但 `*>` 重定向会把 PowerShell 自己的错误流也写进日志，**"Build failed." 这类字样可能来自外层包装**，
先看有没有 `error CS`。

## 跨阶段欠账

- **子窗口合成点击**：P4 组合设置、P5「重新绑定」、P7「移除/确定移除」三处都点不中，
  三处一律退回 `EmitSignal(Pressed)` 并打印留痕（`AUTHORING_NOTE` / `DECK_NOTE` / `ROOM_NOTE`）。
  **本轮查清了不是坐标问题**：把同一控件按三种方式推事件（对话框自己的 viewport + canvas 坐标 /
  同一 viewport + 屏幕坐标 / 主 viewport + 老写法反算），`GuiGetHoveredControl()` 三次全 `null`
  ——事件根本没进对话框那一层。下一步两条路：把这类对话框从 `Window` 改成屏内 `Control` 覆盖层，
  或用键盘驱动（`GrabFocus` + `ui_accept`）。两条都没做。
- **内建词条释义只覆盖 11/19**（`KeywordGlossary`）。其余显示"未提供"。补齐要逐条读引擎实现，属内容工作。
- **战报不记资源点与逐张抽牌**（刻意，见 `BattleLog` 类注释）。玩家反馈"看不到抽牌"再议。
- **房间密码 / 观战延迟没做**（明确降级，理由见计划 P7 段）。要真做都得动引擎协议或角色设计。
