## 1. 建议版本目标

Beta.4 主交付为「对局自动推进可靠、生成卡面一致、原生卡包可导入和编辑」。保持工坊现有的两张入口卡牌与抉择式过渡，保持对局布局与操作方式。引擎决定规则、AI 决策与胜负；前端负责安装文件、编辑交互和展示。

| 优先级 | 工作 | 完成标准 |
| --- | --- | --- |
| P0 | 回合开始抽牌不依赖玩家下一次操作 | 无输入等待时按事件自动播放；0.2 秒保底消费；不重复演出 |
| P0 | 玩家后手时 AI 自动开始第一回合 | 换牌结束即可推进；无需玩家先提交操作；不会重复启动 AI |
| P0 | 无完整卡图的对局牌复用工坊母版 | 单位／指令／反制、字体、裁切与工坊一致；背面和场上缩略表现保留 |
| P0 | ZIP 卡包导入、安装、启用与重启后保留 | 使用后端原生目录格式和加载 API，进入收藏、构筑、真实试打 |
| P0 | 原生卡包接入后端 AssetEditor | 提交临时资产、版本／依赖、转正／放弃由后端执行；无需用户编辑 sidecar／lock |
| P1 | Inspector 能力同步和旧数据迁移 | 无损保留原生结构；校验与当前引擎一致；旧卡组、国家、卡图不丢失 |
| 独立阶段 | 服务端／联机接入 | 先解决源码完整性，再验证两客户端完整流程；本轮不能仅因编译前端成功就承诺可联机 |

联机建议独立验收后再决定是否并入 Beta.4，不能阻塞前三项缺陷修复及卡包导入。当前存在服务端构建阻断，见第 8 节。

## 3. 已确认的接口与真实缺口

| 能力 | 当前后端 | 当前前端与接入要求 |
| --- | --- | --- |
| 加载卡包目录 | `EngineHost.TryLoadCardPack(root, out failure)`、`LoadCardPacks(directory)` | 现有入口主要发现随游戏附带的目录；增加用户安装根与刷新流程 |
| 重载与卸载 | `TryReloadCardPack`、`TryUnloadCardPack`、`UnloadCardPacks` | 对局快照冻结；重载／卸载有对局门禁。前端不能修改正在使用的安装目录 |
| 资产注册与诊断 | `PackageRegistrar.Register(root, manifest, registry, domain)` | 现有 `LoadPackContent` 使用临时注册表，只取 DTO；编辑器需建立持续有效的共享注册面 |
| 原生编辑 | `AssetEditor` 及 `EditorSessionRequest.Edit/CreateNew` | 工坊仍保存 `diy-packs.json`、`diy-cards.json`；尚未接入后端编辑会话 |
| 保存、版本、依赖 | `Commit`、`SetVersion`、`SetDependencies` | UI 按返回值更新，不自行派生 GUID、比较版本或更新 lock |
| 转正与放弃 | `Promote`；`EndSession(Save/Discard)` | **Save 在这里等于转正**，不是普通草稿保存；产品按钮必须区分 |
| 实际刷新 | `AssetEditor.Reload` + 配置的 `AssetLoader` | 未注入 loader 时只计算计划；loader 无 sink 时不落地。不能把 `unchanged/ok` 当作实战生效 |
| ZIP 解包安装 | 尚未找到直接接收 ZIP 的入口 | 前端实现受控的文件安装层，再调用以上原生 API；无需重写卡包规则 |
| 跨进程编辑 | `editor.*` MCP 工具 | 仅 Authoring 模式登记；当前 `Orc.Server` 启动的是 Player 模式，不能向它直接调用编辑工具 |
| 参数表单描述 | 资产元数据不等于完整语义参数 schema | Inspector 仍需版本化适配层；不从 GUID／版本元数据推断玩法参数 |

特别注意：`TryLoadCardPack` 的成功代表包目录进入宿主目录集，不能单独证明资产注册、lock 计划、卡牌准入和对局装配全部成功。完整导入须逐层检查。

## 4. 安装目录与包发现

建议在用户目录建立独立安装区，路径是方案建议，不是已有实现：

```text
user://workshop/
  installed/<package-id>/       完整原生包与随包资源
  staging/<import-id>/          解包、校验、安装事务
  backups/<operation-id>/       被替换包与迁移前备份
  catalog.json                 启用状态、安装来源等客户端信息
```

`catalog.json` 不替代原生 manifest、sidecar 和 lock。版本与依赖的真源仍是后端格式。

当前 `RuntimeGameData.ReadTree` **只复制 JSON**，且导出数据按内容哈希放入 `runtime-data/<hash>`，启动时还会重新写入。用户包不能安装到这里；否则脚本／图片会遗漏，升级也可能使安装失效。随附包继续作为只读基线，用户安装区持久保存完整文件。

包发现合并随附根与用户根。对相同包身份确定一个有效来源，避免同一个 GUID 因原包和编辑副本重复注册；新对局只冻结当前明确启用的集合。导入、重载或迁移完成后，统一刷新包描述、收藏、卡组有效性、卡图索引与工坊列表。

## 5. ZIP 导入／导出的完整流程

1. 文件选择器接受 ZIP；支持 manifest 位于根目录或一个外层目录，先识别包根，不猜测多包归属。首版每次导入一个原生包。
2. 解包到 staging，检查解析后绝对路径始终位于该 staging 内；拒绝绝对路径、`..`、符号链接／reparse 跳转以及大小写冲突文件。设置可配置的文件数、展开字节和路径长度上限，数值由实际卡图包测试确定，不冒充引擎限制。
3. 由后端解析 manifest v2、sidecar 与 lock，生成结构化诊断；非法结构阻止启用。资产级隔离与告警按后端报告显示，明确可用／警告／无效数量。
4. 预览包名、卡牌网格、词条、来源与诊断。缺卡图显示模板占位；缺依赖、非法版本或冲突必须点名。
5. 安装事务采用暂存、备份、切换、失败恢复；结构和资产身份保持原样，不自动转正、改 GUID 或重写第三方脚本。
6. 调用后端加载／注册／装配，再刷新客户端目录和新对局快照。安装成功、启用成功、可构筑和可试打是不同状态。
7. 验证重启仍能发现包；更新游戏后用户包、图标与卡图保留。

同名策略：同身份同内容为重复导入；同 ID 同包 GUID 的不同内容走显式更新预览；同 ID 不同 GUID 报身份冲突。不得直接改 ID 来伪造「另存副本」，因为这会影响应用 ID、资产 GUID 与依赖引用。包版本是内容指纹，不以字符串或大小判断新旧。

导出原生正式包时包含源文件、sidecar、两域 lock 与必要资源，默认不包含 `.tmp`、备份及历史归档。导出前按依赖闭包检查，不能因「当前画面只显示这张卡」就丢掉它引用的效果／处理器。草稿如需跨机保存，须明确标为编辑备份，不能伪装为可实战正式包。

## 6. 后端编辑器与 Inspector 接入

建议在桥接层增加 `WorkshopAssetService`、`NativeCardDocumentAdapter` 等适配器。这些是**拟新增的前端桥接类名，不是后端已有 API**。UI 继续只接收 DTO、诊断和编辑命令。

编辑链路：

```text
选择包 → BeginSession → List/GetAsset → Inspector 编辑完整原文
       → Commit（写临时包）→ 编译／依赖诊断 → 测试域真实试打
       → Promote（用户完成编辑）→ 后端正式 lock → 新局采用
```

- `Commit` 负责保存临时编辑；`Promote`／`EndSession(Save)` 才转正；`Discard` 才放弃。不能把三个按钮映射为同一个「保存」。
- 当前 `Commit` 委托会话写盘，`Reload` 则消费已有注册表；接入时必须验证新资产版本已注册、转正后 `.tmp` 移除不会留下失效源路径。先验证注册／实际装载闭环，不能把提交结果直接当运行态更新。
- 已有内置卡继续可修改：在用户工作区建立保留身份的可编辑副本，经编辑器修改临时包；不直接改安装缓存。只选择一个有效来源，防止原定义与覆盖效果同时执行。
- `InspectorDocument` 可继续管理界面撤销／重做，但不自行生成版本或 lock。临时 UI 包装字段不能写入原生资产。
- 原生 JSON／预制体作为真源；有限表单只改用户实际操作的字段，保留其他字段、stableKey、注入目标和事件身份。无法无损映射的结构只读展示原文与原因，不降级重建。
- 每个可编译声明仍需单独验证实际挂载；文本解析成功、资源保存成功不等于该效果已执行。
- 修正 `DiyInjectionCatalog` 的过期结论：当前仍将所有非空 band 拒绝，而示例包已使用 `Rewrite`／`Commit`。应按具名目标的实际触发器类型及载荷检查组合，逐项加入回归，不能一口气取消所有注入门禁。
- 资产元数据没有提供完整表单 schema；不新增「某张卡专用触发条件」。仍采用时机、对象、条件、动作的通用组合。

临时包恢复是待确认的后端缺口：当前 `BeginSession` 遇到已有 `.tmp` 会拒绝，文档没有恢复会话 API。前端必须检测、保留并解释残留临时包，不能静默删除。需确认后端提供恢复／清理入口，或确认可通过现有 API 受控重放；未验收前，不承诺崩溃后草稿可继续编辑。

## 7. 旧数据和呈现兼容

| 来源 | 迁移办法 | 禁止出现的结果 |
| --- | --- | --- |
| 原生 v2 包 | 直接保留包／资产身份，经后端编辑 | 重生成 GUID、丢 sidecar 或依赖 |
| 内置卡编辑覆盖 | 按原声明合并可编辑字段，验证每条效果恰好一次 | 原效果与覆盖效果重复执行 |
| 旧 `diy/` 卡、旧参考源卡 | 先生成迁移预览和 ID 映射，验证卡组引用后原子迁移 | 迁移后卡组静默少牌或指向另一张卡 |
| 不可序列化／不可无损转换的旧效果 | 原数据继续保留并标为旧格式，列明阻挡 | 保存一次就抹掉复杂效果 |
| 自定义国家、词条与卡图 | 保留完整定义、图标、原图、裁切和字号布局 | 国家退回四个、卡图失效或反复裁切 |

已确认旧自定义国家通过 `WorkshopAuthoring.Configure → Faction.RegisterCustom` 注入；当前原生包交接格式没有说明同等声明如何独立携带、安装及在服务端初始化。词条已有原生 `keywords.json.program`，国家仍需约定。这是迁移依赖，不能用默认国家替代，也不能把只在本机注册成功当成可移植。

「基础卡包／扩展包」是现有工坊关系，不能直接重新写入已退役的 manifest 包级 `dependsOn`。玩法依赖用后端资产级引用；扩展包展示归属、卡图路径等呈现元数据需约定独立的可往返契约。交接文档的 sidecar 示例实际使用依赖字段 `version`，字段表部分称 `versionConstraint`；以 `AssetMetadataJson` 的实际读写器为准，前端不手拼另一套 schema。

对局生成卡面修复只替换完整卡牌展示中的旧绘制路径，复用工坊 `CardFace` 的母版、字体与裁切。隐藏牌继续显示背面；总部、场上缩略单位、费用变更和状态标记继续使用现有对局交互和信息覆盖层。

## 8. 联机调研与后端待办

新的正式方向是 Godot 对局客户端使用 `Orc.Client`，通过 NDJSON/TCP 消费 `notify/view`、`notify/segment` 与选靶消息；对局引擎和 AI 在 `Orc.Server`。创作编译留在独立创作宿主／桥接层，不塞进网络对局客户端。单机若迁移到服务端，也应采用同一协议，不并行维护两份规则真相。

目前不能直接开始宣称「接几个按钮即可联机」：

1. 本机服务端测试编译失败：`src/Orc.Mcp/McpService.cs(51,9): CS0234 Orc.Mcp.Tools 不存在`。调用方引用 `Orc.Mcp.Tools.ToolRegistration.RegisterAll(this)`，文件未找到且不在跟踪清单内。
2. `git check-ignore -v src/Orc.Mcp/Tools/ToolRegistration.cs` 命中 `.gitignore:30 **/tools/`。Windows 上大小写规则可能导致源码漏交；需后端确认并补交完整工具目录。不能在 Godot 中造空注册器绕过。
3. 服务端以 Player 模式构造 MCP 服务，`editor.*` 不开放；联网对局和创作会话必须分别配置。
4. 当前协议段不补历史、目标候选 index 从 1 起、断线后用 seatToken 恢复并拉全量；需要主线程消息队列、序号去重、过期选靶关闭与动画重建策略。
5. `packFingerprint` 是内容对账，不是卡包自动传输或防作弊保证；不同包不能以「连接成功」视为同步完成。

后续联机实施需要：本地服务端自包含发行、开房／加入、座位与就绪、卡组校验、AI 座位、选择请求、断线恢复与终局。现有对局演出按服务端事件适配，保持外观。网络卡包传输、公网匹配、账号、观战及历史回放不纳入此版本的既定承诺。

可转交后端的具体问题：补交 `Orc.Mcp.Tools`；明确 `.tmp` 恢复／丢弃入口；明确自定义国家和呈现资源的包内契约；确认 AssetLoader 的正式／测试域如何接到当前新局快照及实际 sink。上述问题只记录与验证，本次未向其他开发者发送消息。

## 10. 验收与发布要求

- **无输入推进**：固定玩家先手／后手各建局，完成换牌后不点击；回合开始抽牌只播一次、AI 首回合完成并交回。连续多回合覆盖，0.2 秒保底轮询不能重放事件或启动第二个 AI 驱动。
- **卡面一致**：单位／指令／反制、无图／插画／完整卡面、被编辑内置卡，覆盖手牌、放大预览、抽牌与选择；官方完整卡面和隐藏牌不被误合成。1280×720 与 1600×900 检查。
- **导入**：根目录／单包装目录、中文路径、重复导入、身份冲突、无效 manifest、缺 sidecar、锁冲突、路径越界、超限、中断恢复、资源缺失。
- **编辑**：创建、编辑、提交、撤销、放弃、转正、重开、残留临时包；确认版本严格递增、GUID 派生由后端完成、正式与测试域不混淆。
