2. 部署的落点与目标独立保留；空位部署后继续选靶；取消不扣费、不部署、不产生半截效果。动态生成卡牌也接入预打出。
3. 保留跨段“其”的目标复用、原生卡包/扩展包和可编译 DIY 卡联机同步，以及 Android 完整解析器、内置房间和系统文件能力。
4. 客户端 705 项、原生引擎 1360 项测试通过；12 个界面、534 张卡池检查通过。Windows 导出、工坊、真实更新器及升级后程序通过。
5. 最终 APK 已在 Android 35 x86_64 模拟器安装，图形调试与三条部署输入流程、文档/图片读写、编译、训练、开房同步、联机效果及回放验证通过。ARM64 已打包，尚无实体手机实测。
6. 卡库 / 卡组 / 工坊保存前留环形备份（`cards.json.bak1..bak3`，只留 3 份）。读失败时提示行会直接说
   "上一版备份在 X，改名覆盖原文件即可回滚"，不是只写日志。备份写不出去就让这次保存失败——
   "以为有后路其实没有"比直接报错更糟。

## 保留事项

- 检查器的 161 项动作目录不等于全部机制已可执行：其中 **57 项这版能真跑**、**104 项是预览**
  （动作选择器已按「alpha 可用 / 预览（后续引擎版）」分区，并写明每项编不出来的原因）。
  无法无损编译的声明继续保留为草稿。分区判据取自编译器，引擎补上机制后会自动变绿。
- 卡组里的 DIY 卡引用（`diy/<guid>`）：删卡后再导入同一张卡会**沿用原编号**，卡组自动接上；
  编号被占用而必须换号时仍会断链，卡组编辑器里那一行显示「⚠ 这张卡在本机找不到了」并给「重新绑定」。
- 存档版本判定收在 `SchemaVersioning` 一处（区分"存档比游戏新"与"格式太旧"，都保留原文件）；
  迁移入口 `Migrate<T>` 目前只有 v1，真升 v2 时才需要加步骤。
- 对局内「行动记录」面板分三页：战报（完整行动序列，只读不回放）、弃牌堆（弃牌与手牌上限烧掉，两方分开）、
  词条（带参值与携带者）。战报条目只来自引擎给的表现步骤与前端自己发起的动作，不推断规则、不补数字；
  上限 2000 条，超出丢最旧并写明条数。
- 词条释义由界面侧 `KeywordGlossary` 维护，只收核对过引擎源码的 **11 条**；其余词条明说"引擎未提供"，
  不编释义。老兵/隐蔽/被抑制不进词条页（卡面已有徽记）。
- 我方回合有可见倒计时（75 秒，最后 20 秒变色），**超时只提示不结束回合**——alpha 阶段强制超时风险大于收益。
- 房间可起名（局域网列表显示的就是这个名字，改名不必重开房间）、可固定端口（并写明公网要不要做端口映射）、
  加入失败会退避重试并把 socket 报错翻成人话、「房间成员」里可移除已连接的人（对局中移除等同于该座位认输）。
  **没有房间密码**：服务端协议没有口令字段，客户端自校验等于假安全；房间真正的门是房主逐条批准入场。
  **没有观战延迟**：不绑座观战者是全知的（能看到双方手牌），延迟挡不住泄牌，只是把它推后几十秒。
- 手机切后台再回来会**明说连接状况**：回前台主动发一次 `room.info` 确认（不拿"没报错"当"还连着"），
  然后给结论（正在确认 / 正在重连 / 已恢复 / 没恢复）。单机对局与 3 秒以内的切出不提示。
  提示是顶部横幅，不挡操作，**不负责重连**（重连仍由房间屏循环驱动）。
  这一项**只在桌面探针里验过**，Android 真机切后台仍待验。
- 服务端子进程随 UI 退出由引擎保证（`ManagedInstance` 自动追加 `--parent-pid <UI 进程>`，
  `ParentWatchdog` 每 2 秒轮询）。实测：只杀 UI、不带 `/T`，子进程 2.1 秒退出、端口可再绑。
- 本轮未全量重生成官方卡池，旧生成物及自动解析覆盖仍需逐项扩展。
- **本轮未发版**：版本号仍是 `2.0.0-alpha.5`，没有新发行目录、tag 或推送。
  发行说明草稿在 [RELEASE_2.0.0_ALPHA6_DRAFT](../release/RELEASE_2.0.0_ALPHA6_DRAFT.md)；
  `check-consistency.ps1` 目前 `CONSISTENCY_OK`，改版本号必须与发行目录同时动。
  发版前唯一硬门槛是 **ARM64 实体机验收**。
- 下一步优先做 ARM64 实体机验证与复杂 DIY 机制覆盖，不能用模拟器或卡图存在代替规则验收。
