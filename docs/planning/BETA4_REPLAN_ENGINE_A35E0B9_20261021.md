## 3. 后端变化对前端的具体影响

| 变化 | 已核对的源码 | 前端必须调整的行为 |
| --- | --- | --- |
| 包版本改为当前 sidecar 规范内容指纹 | `PackageVersion.ComputeContent`；旧 `Compute` 改名 `ComputeLayout`；AssetEditorSession 使用新算法 | 不手算包版本；不按版本串排序；ZIP 完整文件哈希仍单独保留，不能用 sidecar 指纹代替图片和源文件的重复内容判定。 |
| 同一 sidecar 的版本按组变化 | `AssetEditorSession.SetVersion/CommitPrefab/AutoNext` | 保存／设版本后刷新宿主和同组 trigger／handler；手写版本大于组内最大值，不能只改一行显示。 |
| 删除宿主级联删除内含资产 | `AssetEditorSession.DeleteAsset` | 删除前展示影响范围，确认后刷新相关资产与依赖诊断；不能只提示“删除此资产”而隐藏级联结果。 |
| 新建／提交源身份校验更严格 | `VerifyDeclaredSourceId`、`CommitCard`、`CommitPrefab` | 不改 sidecar 来“让错误通过”；源 id 不符、只有内含没有宿主等错误保留草稿，定位到对应源文件。 |
| `versions/**` 为编辑禁区 | `AssetEditorSession` 路径校验 | 历史只读；不把编辑历史文件当成恢复版本的入口。 |
| 编辑器枚举包受授权根限制 | `AssetEditor.ListPackages/IsUnderAuthorizedRoot` | 当前 NativeWorkshop 把 shipped/packs 放在 PackageRoots，但 policy 仅授权 installed；新后端会过滤 shipped。必须重设用户工作副本与引用来源的关系，不可扩大写权限到发行目录来绕过。 |
| 转正正式落地增加事务与回滚 | `BuildPromotionPlan/ApplyPromotionPlan`；`PromoteFailed` | 后端正式包写入失败与前端激活卡池失败分两阶段处理。后端已回滚时保留临时会话和错误；不要再执行一套会破坏恢复结果的盲目覆盖。 |
| sidecar 发现由清单与约定磁盘位置取并集 | `PackageScanner`、`PackageRegistrar.ReadSidecars` | UI 的资产数和诊断来自注册结果；不能只数 manifest.metadata。声明的 sidecar 缺失仍是包级错误。 |
| 同 GUID 重复 lock 返回结构性错误 | `LoadListPlanner.DuplicateLockEntry` | 原样显示冲突条目并阻止激活；不能前端去重后冒充校验通过。 |
| 声明冲突在依赖排除后计算 | `LoadListPlanner.Plan` | 展示后端的实际有效资产和问题，不自行提前判冲突。 |
| 包 GUID 精确版本查询 | `AssetRegistry.VersionsOf(Guid,...)` | 同 ID 不同 GUID 的来源冲突要指明身份，不能把查询结果混成一个版本列表。 |

后端仍未提供 ZIP 导入 API；ZIP 文件运输继续由前端负责，注册、版本、依赖与规则执行归后端。

## 4. 本轮重新核对出的前端问题

### 4.1 依赖可见性需要专项修正

当前 `NativeWorkshop.Create/Begin` 配置：

```text
EditableRootPolicy：user/workshop/installed
PackageRoots：installed + shipped/packs
```

新后端先按 policy 检查包目录再读取清单，因此仅把自带目录加进 PackageRoots 已经不足以让编辑器看见它。现有新包测试使用“已经安装在用户目录的 demo”为引用来源，不能覆盖“只存在于发行目录的自带依赖”场景。

拟定处理：将确需引用的自带依赖制作为**用户作者工作区中的副本**，与正式启用清单分开；编辑器策略只授权用户工作区，发行源始终只读。记录副本来源及其身份／指纹，原始包更新后提示差异。具体目录约定在 T1 落地时一次定清，不能为修可见性而引入重复运行时包。

### 4.2 期望引用不能等同扩展包归属

当前 `OrcEngineHost.LoadPackCards` 用 `manifest.RequiredPackages.Count == 1` 推导 `PackDescriptor.BasePackId`。新交接再次明确：`requires[]` 是期望引用声明，不代表扩展包关系，也不负责资产依赖解析。

必须停止据此把新建独立包显示成扩展包。扩展归属使用独立的前端表示元数据，旧 DIY 的 `BasePackId` 保留；新导入格式没有关系声明就显示为独立内容，不猜测。资产依赖仍只认后端 sidecar。

### 4.3 现有 Inspector 不能直接套壳就算适配完成

已检查：

- `NativeEffectInspector.cs` 已有友好入口、高级工具、撤销／重做和编译报告。
- `NativeEffectInspector.Native.cs` 对 `$nativeDraft.PrefabJson` 的友好路径目前展示预制体槽后便返回，并非完整原生预制体图形编辑。
- `InspectorCardRecord` 使用 `$orcEditorSource`／`$nativeDraft` 等编辑器包络，服务旧草稿结构。

因此“把整个 prefab JSON 塞进旧 Inspector”不能解决完整时机／条件／动作编辑，也不能把这些包络写入引擎原生源文件。需要明确的无损文档适配器，把持久数据、编辑视图和实际后端编译结果分开。

## 5. 产品方案：一套完整工作区

2026-10-21 制作前案例调研补充：[KARDS 与优秀制卡／组合编辑案例](../research/DIY_WORKSHOP_UI_CASE_STUDY_20261021.md)。该研究修订下面的空间安排：浏览卡包与单卡制作分开；制作时卡库可收起，不默认三栏加诊断全常驻。后续先验证可交互原型，不能把通用属性树视为完整编辑器。

### 5.1 首页、选择和导入

- 首页继续两张纵向大卡：卡包、扩展包；保留已接受的选择动画。
- 顶部仅保留次级“导入”和管理入口。导入不是第三张主选择卡。
- 导入先展示具体包名、身份、已有／新增卡数、资源与诊断、是否替换；确认后安装。相同文件内容只提示已存在，不反复安装。
- 缺 sidecar、资源缺失、不可执行规则、结构性错误分别显示。不能把“安装成功”写成“所有卡均可玩”。

### 5.2 工作区布局

浏览卡包时，以可搜索、可分页的卡面网格为主，所选内容的操作集中在详情侧。进入单卡制作后，主要空间交给当前任务编辑与大卡面预览，卡库可收起，详细诊断按需打开。窄窗口调整区域而非无限压缩字段；规则页使用选中项的上下文编辑，不能把所有参数常驻展开。

主编辑区采用四个明确页面：

| 页面 | 玩家看到的内容 | 高级内容去向 |
| --- | --- | --- |
| 卡牌属性 | 名称、国家、卡牌类型／单位类型、费用、战斗属性、稀有度；控件来自可用词表，未知值保留 | 原生组件名、源文件与身份放信息面板 |
| 规则与词条 | 时机 → 条件／目标 → 动作；支持通用组合、复制、移动、删除和撤销 | band、注入、wrapper、无法图形表达的程序结构进入高级页，有明确支持状态 |
| 卡图 | 插画／完整卡面来源、裁切、母版切换和即时预览 | 文件路径与表示 JSON 不出现在主流程 |
| 风味与说明 | 卡面文本、风味、说明及解析结果 | 原始文本保留；解析只支持正式 K 语，未知句式明确报错 |

包状态区区分“已安装／已启用”和“有未保存修改／已存草稿／已转正”；规则状态另行显示“可解析／有诊断／可用于新对局”。不要把多个维度塞成一个“正常”。

### 5.3 保存、检查与转正

1. 表单修改进入文档模型，预览即时更新；不立刻触发原生运行时更新。
2. “保存草稿”调用后端 Commit，刷新整组版本和资产，保留撤销基线及未支持字段。
3. “检查”展示注册／加载计划与规则编译结果；计划成功和实际试打成功分别标记。
4. “转正生效”展示范围和诊断，调用后端 Promote；成功后再激活有效包集、刷新图鉴／构筑。
5. 后端转正失败保留会话继续编辑；前端激活失败恢复上一套有效包集，保存失败产物和可重试状态。
6. 离开表单、切包、离开工坊、关闭程序均遵循同一未保存保护；已经保存到临时包的草稿不能无提示遗失。

### 5.4 旧内容、恢复和高级能力

- 自带包编辑采用用户副本，维持身份；旧 SourceCardId 覆盖先检查能否无损迁移，不支持的继续原入口并解释，不能删掉旧数据让新入口看似干净。
- 自定义国家、词条、图标、完整原图和裁切必须出现在迁移／导出范围中；可移植表示格式未定前，不声称跨机器完整支持。
- 已有包和未转正新包的孤立 `.tmp` 都要可发现、可备份／导出。后端无 resume API 时明确给出恢复方式和边界，不伪造无损续接。
- 高级页可看完整源、sidecar、lock、版本、依赖与未知字段；service 与历史版本只读。高级编辑不能污染主流程，也不能绕过后端校验。

## 7. 新基线必须追加的验收场景

- 引用仅在 shipped 的卡包，编辑器可正确显示引用来源，而正式发行目录哈希不变。
- 独立新包即使 `requires` 恰有一条，也仍是独立包；扩展包只有显式的显示归属才继承卡池。
- 原生 prefab 的宿主及至少两个内含资产：连续保存、显式改版本、再次保存，UI 显示组版本一致。
- 删除宿主前展示级联影响，确认后不遗留孤儿；仅删内含资产不会误删宿主。
- 后端 `PromoteFailed` 后旧正式目录不变、临时草稿仍可导出；另测后端成功但前端激活失败。
- manifest 漏列 sidecar、清单声明缺文件、约定目录之外的 sidecar 各自符合真实扫描语义。
- 畸形 lock 重复 GUID 不崩溃、不前端去重，原有效卡池保持。
- 源文件或插画变动、sidecar 内容变动、仅排版／注释变化分别测试，区分 ZIP 字节哈希与包语义指纹。
- 新建包未转正时退出、已有包未转正时退出，重启均能找到草稿且不混入正式构筑。
- 原先 3 项对局 bug 的专项和旧工坊／Inspector／自定义国家／构筑回归继续通过。
- 真正的 UI 操作覆盖输入、预览、错误修复、离开取消、重开、保存、转正、试打，不能全用直接调服务方法代替。
