## 2. 六个真实问题（按痛感排序）

1. **为暂停的功能付 40% 体积**：3D 桌饰 477 MB 原样进 Windows 包和 APK，玩家永远用不到。
2. **卡包与美术写死在 `res://`**：加一个包（如 `牌！Q!!!` 133 MB）全世界玩家一起变重，无法按需。
3. **增量补丁会退化**：pck 大改时单来源分片 943 MB，比完整包还大，只能逼人重装。
4. **`screens` 目录 20k 行、BattleScreen 拆成几十个 partial 文件**：找一处逻辑要跨文件拼，改一个功能的心理成本在涨。
5. **引擎靠 `docs/engine-patches/*.patch` 传输**：补丁会随引擎推进漂移，靠人记得应用。
6. **版本与发版节律乱了**：`VERSION` 还是 `0.0.0-beta.7`，树里却有 beta.7 之后的改动，还并存 `RELEASE_BETA7_HOTFIX` / `HOTFIX2` 两份说明。

## 3. 三阶段方案

### 阶段 0 · 止血（1~2 天，只动打包，不动功能）

| 动作 | 做法 | 预期收益（按实测） |
|---|---|---|
| ① 手机包排除 3D 桌饰 | Android 预设 `exclude_filter` 加 `proto/art/original-cosmetics/models/*` | APK **1079 → 约 610 MB（-43%）** |
| ② 桌面包评估同项 | 桌饰已暂停：要么一并排除，要么做成"可选内容包" | 完整包 1165 → 约 700 MB |
| ③ 第三方大包改可选 | `牌！Q!!!` 等登记为"可选内容"，不默认进主包 | 再省 130~260 MB |
| ④ 固定版本号规则 | `VERSION` 单一真源；beta 期间不允许 hotfix 文档与代码脱节 | 消除发版歧义 |

> ①是最便宜的一刀：一行 `exclude_filter`，出货立刻瘦 43%。

### 阶段 1 · 结构（约 1 周）

1. **资产分层与清单化**
   - `core/`（必装：UI 素材、默认卡池）＋ `optional/`（桌饰、第三方卡包、旧卡池）
   - 包 manifest 增加 `assetBytes` / `requires`，启动时按需挂载，不满足就提示下载
   - 复用现成的 `.orcupdate` 分发管线做"内容包"，不用新造轮子
2. **卡包资产根可配置**：卡图路径从"写死 `res://proto/art/<pack>`"改为"读包 manifest 的 `artRoot`"，支持 `user://` 与外部目录
3. **发版节律固化**：`beta.N` → 只递增 N；hotfix 用 `-hotfix.N` 并在 `docs/release/` 一对一，不允许两份并存

### 阶段 2 · 长期（持续）

1. **UI 拆分**：按域把 `screens` 收敛成 `screens/battle/`、`screens/workshop/`、`screens/menu/`；
   `BattleScreen` 的几十个 partial 合并成 3~4 个真正的组件（Mulligan / Hand / Board / Presentation）
2. **测试分级**：快档（<30s，纯逻辑）＋慢档（全链探针）。改一行不必等 9 分钟导出
3. **引擎集成**：`engine-patches/*.patch` → git submodule 或本地 NuGet feed，消除"靠人记得打补丁"
4. **体积预算**：把"APK ≤ X MB、pck ≤ Y MB"写成发布门禁，涨超就报警
