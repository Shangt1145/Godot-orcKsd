# 积木 Inspector 入口与写回审计

检查范围：运行时注册页面、主菜单及手机返回、DIY 工坊、原生卡牌、兼容 DIY 草稿、词条与效果库、引导教程，以及对应保存和返回事件。此记录不把后端 API 或历史实验代码的存在当成玩家功能已可用。

## 发现和处理

| 发现 | 修复后的入口或行为 |
| --- | --- |
| 工坊顶部已经是积木 Inspector，但卡牌、包内效果和教程仍打开旧 Inspector | 全部进入同一个 `HandlerBlockEditorScreen`；删除旧 `NativeEffectInspector`、旧效果屏及其组合编辑 UI |
| 卡牌页打开积木后缺少当前卡牌上下文，新效果保存后可能没有使用者 | 卡牌 → 规则 → 编辑效果 · 积木 Inspector → 添加或选择效果；保存后自动更新该卡的效果引用 |
| 新建但尚未被卡牌引用的积木效果缺少可靠的重开路径 | 包内效果库列出效果，直接传入目标；保存对话框即使没有引用计数也会列出当前编辑对象 |
| 重开画布可能回到样例；保存对话框的覆盖选项还会重新载入文件并覆盖当前画布 | 从效果入口载入原积木及触发模板；保存选项只设置写回目标，不改画布 |
| 重编已有生成效果可能生成 `.dsl.dsl` 后缀链 | 已有 `.dsl` 产物继续使用同一 ID；原效果作为基线保留 |
| 触发时机藏在保存对话框里 | 积木页顶部可选择模板；保存沿用该选择 |
| 原生卡牌编辑页没有对应兼容编辑器的构筑和试打入口 | 新增“应用并用于构筑”“应用并试打”，保存及准入成功后应用，再进入目标功能 |
| 菜单帮助、设置、首页和手机返回可能绕过积木未保存保护 | 统一检查积木修改；提供保存后离开、继续编辑、不保存离开 |
| 删除的旧源码会残留在短路径运行副本，导致编译出旧界面 | `prepare.ps1` 明确清理已退役的 UI、旧探针及其 UID |

## 兼容边界

旧卡牌、脚本效果和旧声明数据仍保留。存在积木源文件时按原图编辑；没有积木源文件的脚本效果不能宣称已经无损反编译，界面会说明当前画布用于重新搭建，保存后才替换引用。

旧 DIY 草稿和旧词条进入原生“积木工作副本”，原件保留。工作副本复制卡图及国家、词条词汇，自定义词汇使用新 ID，避免两个卡包的词汇 ID 冲突。旧词条的工作副本包含一张使用该词条的练习卡；修改作用于工作副本，不回写原旧格式词条。旧词条参数与主动技能编辑工具保留为原格式的数据维护入口。

工坊首页没有打开卡包时，顶部积木入口先要求选择卡包，避免进入无法保存的画布。构筑、收藏、外观、作战准备、房间、帮助和设置的运行时页面均有菜单或前置页面入口；本次没有发现额外已注册但完全无路由的页面。这个结论不代表对所有后端能力做了功能覆盖认证。

## 验证入口

- `--verify-diy-tutorial` / `--capture-diy-tutorial`：教程完整流程、卡牌自动关联、连续两次重开保存、ID 稳定、返回、恢复、应用、真实试打及旧 DIY 工作副本（含自定义国家、词条）。
- `--verify-native-workshop`：原生包与效果库、积木保存、覆盖、多输出命名、卡图、属性、ZIP、应用与原生部署回归。
- `HandlerDslAuthoringTests`、`HandlerDslEditorTests`、`DiyTutorialTests`：积木数据、写回、执行及教程判定测试。

原来依赖已删除 Inspector 的 UI 专项探针已退役；旧命令别名仍保留，执行当前统一积木流程。解析器和旧数据编译器的后端测试没有删除。
