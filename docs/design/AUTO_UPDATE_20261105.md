# 启动自动更新：设计与被否掉的方案

> 2026-11-05。对应 `proto/bridge/.../Updates/ReleaseFeed.cs`、`proto/ui/screens/Main.AutoUpdate.cs`、
> `OrC.Updater` 的 `--apply` 入口。

## 1 之前为什么麻烦

发版侧早就有完整链路：`release.ps1` 导出 → 按基线算差分（`PatchManifest`）→ 用**真更新器**
在基线副本上应用一遍做验证。麻烦的是玩家这一端：

1. 去发布页找**自己那个构建**对应的补丁（名字里带 `from-<12位构建>`，选错就打不上）；
2. 下载；
3. 打开 `更新游戏.exe`，选游戏目录、选补丁、点更新；
4. 等它装完，再点「启动游戏」。

四步里任何一步做错，玩家看到的是「更新失败」或「更新完还是旧版本」，而不是一句能懂的话。

## 2 现在

启动后后台查一次发布页，发现新版弹一句：

> 发现新版本 2.0.0-beta.4 —— 这版可以用增量补丁更新（8.9 MB），只下改动的部分。
> 更新时游戏会关闭，装完自动重新打开。卡组、DIY 卡与导入的卡图都会保留。

点「现在更新」→ 下载（带百分比）→ 校验 → 拉起更新器 → 游戏退出 → 更新器等进程结束后应用
→ 装完自动重开。另有「跳过这个版本」，那个版本以后不再提示。

## 3 四个决定

### 3.1 游戏不自己替换任何文件

正在运行的进程锁着自己的 `.dll` 与 `.pck`。想「下载完直接覆盖」的结局只有两种：文件被占用而失败，
或者更糟——覆盖了一半，游戏再也起不来。

所以职责切开：**游戏只负责下载、校验、拉起更新器、退出**；替换、逐文件校验、失败回滚仍归更新器
（`Installer.ApplyAsync`，它本来就会等游戏进程结束再动文件）。这条也保证了「手动更新」与
「自动更新」走的是同一段代码，不会出现两套行为。

### 3.2 按构建 id 匹配，不按版本号

补丁是**逐字节差分**。同一个版本号可能对应两次构建（热修、重新导出），字节不同，补丁就打不上。
发版脚本的补丁名里带 `from-<源构建12位>`，正好能精确匹配。

对不上时的顺序是：**精确补丁 → 兼容合集 → 完整包 → 什么都不做**。

最后那个「什么都不做」是刻意的：线上按仓库规则**不上传 1.2 GB 全量包**，所以跨了好几个版本的
玩家其实没有可下的东西。这时候**不提示**比「提示了但下不下来」好，更比「拿一个更旧的版本凑数」好。

### 3.3 用 `/releases` 列表，不用 `/releases/latest`

我们所有版本都是**预发布**（Prerelease），而 `/releases/latest` 只返回非预发布的最新版——
用那个接口会一直返回空，表现为「自动更新永远不提示」。这个坑不写下来，下一个人一定会踩。

### 3.4 开发环境与探针不查

- 编辑器里没有 `.orcksd-build.json`，也没有构建 id，查了只能误报；
- `--verify-*` / `--capture-*` 要的是**确定性**：网络一抖，同一份脚本会给出两种结论，
  而截图会跟着变。另留 `--no-update` 给需要手动禁用的场合。

## 4 被否掉的方案

| 方案 | 为什么不用 |
| --- | --- |
| 游戏内直接覆盖文件 | 进程锁着自己的 dll／pck，必失败；半覆盖会让游戏起不来 |
| 用 `/releases/latest` | 只返回非预发布版，我们的版本全是预发布 → 永远为空 |
| 按版本号匹配补丁 | 同版本可能多次构建，字节不同，补丁打不上 |
| 下完不校验 | 断线／被劫持／半截文件都会变成「装完打不开」，而更新器只信自己的逐文件校验 |
| 没补丁就下全量包 | 1.2 GB 不在线上分发；提示一个下不下来的东西比不提示更糟 |
| 更新完不重启 | 玩家看到的是旧界面，会以为没更新成功 |

## 5 踩到的两个坑

### 5.1 更新器自己会被当成「游戏完整包」

真发布页上每版都挂着 `OrC-KSD-offline-updater-1.2.0-win-x64.zip`。宽松的正则
`^OrC-KSD-(.+)-win-x64\.zip$` 会把 `.` 贪婪吃到 `offline-updater-1.2.0`，于是**跨版本玩家**
被引导去下 74 MB 的更新器，再交给更新器应用——必然失败，提示「更新没成功」。

现在版本段必须长得像版本号，且要与发布版本一致。这条是**用真实发布页数据跑出来的**，
假数据没覆盖到（我构造的样例里只有游戏包）。

### 5.2 `--` 少一个，更新器会「正常启动然后什么都不做」

Godot 吃掉 `--headless` 之类的引擎参数，`--` 之后才是应用参数（`OS.GetCmdlineUserArgs()`）。
少一个分隔符，更新器会打开界面、显示「准备就绪」，然后无视 `--apply`——玩家看到的是
「更新完还是旧版本」。参数顺序抽成 `UpdateLauncher.Arguments` 单独测，就是为了这个。

## 6 测试

**离线（11 条）**：解析、版本比较（`beta.10 > beta.4`、正式 > beta、hotfix > 正式）、
按 buildId 挑补丁、退回兼容合集、退回完整包、草稿与旧版忽略、最新版缺文件时不退回旧版、
校验和按文件名取、下载落盘、校验失败不留正式文件、更新器参数顺序。

**真数据（一次性）**：拿发布页真实 JSON 跑挑选逻辑——beta.3 机器挑到 9.35 MB 补丁；
跨版本机器不提示；已是本版不提示。这条逮到了 §5.1。

**端到端（发版门禁自带）**：真更新器在 beta.3 副本上应用本版补丁 → 结果与完整包逐文件一致
（`PATCH_EXACT_FILES_OK`）→ 升级后的 EXE 再跑一次 `--verify-export`。

## 7 仍未做

- **兼容合集补丁**的自动产出是断的：`tools/find-update-baselines.ps1` 的版本过滤写死
  `^0\.0\.0-(alpha|beta)\.N$`，扫不到 `2.0.0-beta.N` 这一代，`-CompatibleThroughBeta` 对 2.x
  静默失效。要支持跨版本自动更新必须先修它（连带那处 `0.0.0-beta.N` 的硬编码检查）。
- 更新是**启动时**检查的，游戏跑着不会提示。做「运行中提示」需要额外的窗口与退出协调，
  收益不明显（玩家总要重开一次）。
