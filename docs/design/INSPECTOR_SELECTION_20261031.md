## 0 一句话结论

引擎今天把「效果编辑器画什么」的答案**冻结**了：树、数组顺序、无节点 id、13 个错误码、26 个节点。Inspector 选型因此不再是审美问题，而是「哪种形态能 1:1 表达这个树，并且画出来的东西一定存得下」。

**【建议】** 主编辑面用**竖向积木**（序列＝上下顺序），值层用**内联卡片＋表达式抽屉**，节点图降级为**只读结构总览**（可后置）。理由见 §3。

## 1 契约对界面的硬约束

| # | 约束 | 出处 | 对界面的后果 |
|---|---|---|---|
| C1 | 执行顺序＝`actions[]` 数组顺序；**没有** exec 引脚／`next`／跳转边／环 | SPEC §2.1–2.2 | 「然后」不能是连线，只能是上下位置 |
| C2 | 节点**没有 id**，定位恒用节点路径（`actions[0].else`） | SPEC §2.3、§14.2 | 画布内部 id 不得写进文件；错误必须能落回具体块 |
| C3 | **后端不做图→树**；输入不是树＝直接拒绝并指明位置 | SPEC §2.7 | 折叠算法必须在前端，且折叠失败要当场说 |
| C4 | 出度>1：纯表达式可**复制**；含 `await`／副作用必须**拒绝**并改用 `let` | SPEC §2.7、FRONTEND §8 | 自由连线会在保存时变成硬错误 |
| C5 | 前端**禁止** DSL→csx（连预览都不许） | FRONTEND §2 | 不能做「实时看生成代码」的卖点 |
| C6 | 前端必须**本地实现 13 条校验**，码与路径与后端一致 | SPEC §14.1、§15.1 | 校验器是 UI 的一等公民，不是后端的补丁 |
| C7 | 封闭集：10 内建 op ＋ 24 目录节点 ＋ 5 表达式变体 ＋ 17 算子 ＋ 5 引脚类型 | SPEC §3–§6 | 控件种类有限，可以做得很实 |
| C8 | 嵌套深度上限 64 | SPEC §2.5 | 缩进/嵌套要能收，不能无限内卷 |
| C9 | `script` 在 v1 **没有值通道**（`inputs`／`outputs` 只是声明） | SPEC §3 | 脚本不是万能逃生舱，不能拿它兜底 |
| C10 | `choice` 运行期抛 `NotSupportedException`（等前端桥接 S10） | EXCLUSIONS 运行时能力现状 | 现在放出来＝作者一点就炸 |

## 2 两种候选逐项对比

同一份任务、同一套契约，比较四个操作轴（条件、循环、前序结果引用、子效果配置）＋ 四个工程轴。

| 维度 | 积木式（Scratch 风格） | 节点图式（Blender／UE 风格） |
|---|---|---|
| **执行顺序**（C1） | 天然：上下就是先后，无额外概念 | 要画 exec 边；但这条边**不存进文件**，是画布自造的语义 |
| **条件分支** | 容器块内嵌两臂，缩进即作用域 | 双出口连线，臂与臂之间的边界靠布局读 |
| **循环** | 容器块＋次数/集合引脚 | 同样，但循环体是一圈边，读「哪段在体内」更费眼 |
| **前序结果引用** | 绑定以「名字芯片」出现，插在引脚上 | 值连线跨节点，长距离时线会打架（需要 reroute） |
| **子效果配置** | 引脚即行，一行一个值 | 引脚散布在节点四周，小节点还行，8 引脚节点开始乱 |
| **出度>1**（C4） | 结构上不鼓励：一个值块就一个位置；要共享就 `let` | 天然鼓励：随手拉第二条线 → 保存时才被拒 |
| **错误定位**（C2） | 块高亮＋块内红点，路径天然对应 | 节点高亮，但「同一节点被复制成两份」后路径对不上 |
| **保存前可判性**（C3/C4） | 高：画不出非树 | 低：画得出、存不下 |
| **学习成本（目标用户：不懂代码的玩家）** | 低：顺序＋嵌套＝日常直觉 | 中高：要先理解「执行流」与「数据流」两套线 |
| **实现成本（我们）** | 中：布局是线性＋缩进，虚拟滚动即可 | 高：画布、缩放、避让、连线、自动布局、折叠 |
| **手机端** | 好：竖向滚动 | 差：小屏拖线是公认的痛点（本项目要发 Android） |
| **目录增长（C7 会变）** | 新节点＝调色板多一项，零改动 | 新节点＝多一种形状/引脚布局，可能要调版式 |

**【建议】判据只有一条硬线**：节点图式的核心卖点（任意 DAG）在 C3/C4 下**不可保存**。允许作者画出存不下的图，再在保存时说「不行，请改」，等于把编辑器的失败留给作者收拾。这一条足以定选型，其余都是加分项。

## 3 结论（建议，待确认）

1. **主编辑面＝竖向积木。** 一个 `actions[]` 就是一列块；`iterate`／`branch`／`loop`／`choice` 是容器块，子体缩进显示。这正好是 DSL 的形状，不需要任何「折叠」步骤——**C3 的算法难点直接消失**。
2. **值层＝引脚上的内联卡片。** 点引脚弹「取值抽屉」：字面量／绑定／视图字段／读取／算子。表达式是一棵树，用缩进式小面板编辑，不做自由连线。
3. **节点图保留但降级**：一个**只读**的「结构总览」页签，用于看清整体形状（尤其 8 层嵌套时），不支持编辑。**后置，不进第一版。**
4. **不做的**：实时 csx 预览（C5 禁止）、自由连线、节点 id、图内跳转。

> 这与 10-31 交接里「上一轮助手倾向积木为主、节点图为高级视图，但未获确认」一致，但**依据换了**：不再是偏好，而是 C3/C4 的硬约束。

## 4 原语整理

### 4.1 四层，别混

| 层 | 内容 | 数量 | 谁维护 | 能否被作者组合 |
|---|---|---|---|---|
| L0 表达式 | 5 变体（`lit`／`var`／`view`／`read`／算子）＋ 17 算子 | 5＋17 | 契约冻结 | 是（树内嵌套） |
| L1 内建 | `sequence` `branch` `loop` `while` `iterate` `choice` `let` `write` `ask` `script` | 10 | 契约冻结 | 是（容器嵌套） |
| L2 目录动作 | `damage` `draw` `buff` `grant` … ＋ `stop`／`interrupt` | 24＋2 | **引擎扫描自动生成** | 是（挂到序列里） |
| L3 组合动作 | 由 L1＋L2 拼出的常见套路（如「受伤计数」「部署时抽牌」） | 0（待建） | **我们**（预制体/模板） | 作为模板插入，展开成 L1/L2 |

**【建议】** 交接里说的「基础原语 / 组合动作 / 旧别名」正好对应 L2 / L3 / （见 4.3）。分层之后，评价标准也清楚了：L2 的完备性看引擎，L3 的完备性看「作者最常拼的十个套路有没有模板」，**不是看目录条数**。

### 4.2 双目录问题：必须先定真源

现在仓库里同时存在两套「动作目录」：

| | 旧：工坊 JS 词表 | 新：Handler DSL 目录 |
|---|---|---|
| 位置 | `InspectorVocabulary`／`InspectorDocument.Operations`（内嵌 JSON `contract.ops`） | `HandlerCatalogFacade.GetCatalog()`（引擎反射扫描） |
| 条数 | **161**（其中 57 可跑 / 104 预览，见 STATUS.md） | **26**（24 动作＋stop/interrupt） |
| 语义 | 旧 Kards-Desktop 的 Inspector 模型 | 契约冻结的 handler DSL |
| 判据 | `DiyCapability` 走 `DesktopNativeLowering` 试编译 | 目录由标注＋扫描产生，装载期再校验 |

**【契约事实】** 两者不是同一个东西，不能互相顶替：新 DSL 里出现旧 op 名＝`node-unknown`。

**【建议】** 把新目录定为**唯一真源**，旧 161 项按三分类处理（这就是「旧别名」工作的实质）：

1. **等价**：旧 op 能一一映射到某个 L2 节点 → UI 显示名沿用旧中文名，DSL 写新名；
2. **可组合**：旧 op 等价于一段 L1＋L2（如「条件伤害」＝`branch`＋`damage`）→ 收进 L3 模板；
3. **不可表达**：v1 表达不了的（见 §5 缺口）→ 明确标注「当前版本做不到」，**不静默降级**。

这一步必须**逐条核对**，不能凭名字猜。产出应是一张 `旧 op → 新节点/组合/不可表达` 的表，作为 L3 模板的输入。

### 4.3 别名只能活在 UI 层

**【契约事实】** DSL 只认目录里的 `name`；未知名字直接拒（`node-unknown`），**不做无损保留**（SPEC §0.4）。

所以「保留旧别名」只能有两种落地：
- UI 显示名映射（DSL 永远写新名）——推荐；
- 迁移期一次性转换旧数据（不是运行期兼容层）。

**不能**做「DSL 里写旧名、后端翻译」——那等于在冻结契约外面再长一套语法。

### 4.4 目录没有中文名（真问题）

**【契约事实】** `HandlerCatalogNodeDto` 只有 `Name`（英文 op，如 `damage`／`fetchFromDeck`／`pin`），没有 title/displayName。`EnumValues` 也是英文值。

对「不懂代码的玩家」这是硬伤：作者看到的是 `damage`、`pin`、`rerunAuras`。

三条路：

| 方案 | 做法 | 代价 |
|---|---|---|
| A. UI 侧词表 | 我们维护 `op → 中文名 + 一句话说明`，像现有 `KeywordGlossary` 那样 | 会与目录漂移；新增节点默认显示英文 |
| B. 引擎加 `title` 字段 | 目录增量加可选字段，只升 `catalogRevision`（SPEC §1 增量变更） | 要引擎侧点头；但这是最干净的一次性投入 |
| C. 混合 | UI 词表兜底＋未收录时显示英文并标「未命名」 | 诚实，但作者体验断崖 |

**【建议】** 先按 C 落地（不阻塞），同时向引擎侧提 B。理由：`catalogRevision` 的增量变更通道本来就是为这种「加可选字段」设计的，而且**中文名属于目录内容，不属于前端**——放前端一定会漂移。这与项目已有的「词条释义由界面侧维护、只收核对过的 11 条」是同一个取舍，但动作目录的更新频率比词条高得多。

### 4.5 按作者意图重分组（UI 侧，不改目录）

目录是按方法名派生的，分组是乱的（`death` 排在第一个）。UI 需要一层「意图分组」：

| 分组 | 节点 |
|---|---|
| 造成与消灭 | `damage` `kill` `death` `silence` `pin` |
| 属性与词条 | `buff` `grant` `revoke` `setKeywordValue` `costMod` `deployCostMod` `rerunAuras` |
| 手牌与牌堆 | `draw` `addToHand` `shuffleIn` `fetchFromDeck` `pickHandCards` |
| 战场位置 | `move` `battle` `upgrade`（＋缺口：入前线/入支援线，见 §5.5） |
| 资源 | `gainPoints` `losePoints` `gainPointSlots` `losePointSlots` |
| 流程 | `stop` `interrupt` |
| 交互与查询 | `ask` `choice` |
| 控制流 | `sequence` `branch` `loop` `while` `iterate` |
| 变量与视图 | `let` `write` |
| 逃生舱 | `script`（建议默认折叠，二次确认才展开） |

## 5 契约缺口（要反馈给引擎侧，不是我们能修的）

这一节是本次阅读契约**新发现**的问题，按影响排序。

### 5.1 读不到「被遍历实体」的属性 ★最严重

**【契约事实】** `read.of` 封闭集只有 `self`／`viewer`（SPEC §4.5，`HandlerDslReader.cs:56`）。`view` 取的是**当前执行帧**的视图字段。

后果：`iterate over targets as t` 之后，**没有任何表达式能读 `t` 的防御力／攻击力／费用**。于是这类最常见的效果写不出来：

> 对目标造成伤害；**若目标防御 ≤ 2**，则抽一张牌。

`t` 只能当实体传给动作引脚（`damage.target`），不能进比较。而 `script` 也救不了（C9：脚本没有值通道，`t` 进不去）。

**【建议】** 给 `read.of` 加第三个取值（如 `"of": "var"` ＋ `name`），或给 `read` 增加 `"of": "expr"` ＋ 实体表达式。这是**破坏性/扩容级**改动（封闭集放宽可算增量，但语义要新增），需要引擎侧定。

### 5.2 没有「查询某方所有单位」的原语

**【契约事实】** 26 个节点全是动作，没有 `all`／`random`／`first` 这类纯查询节点；`EXCLUSIONS` 明确把 `OwnerUnits` 排除（理由：它是查询不是动作，且隐式宿主映射会出错）。

后果：`iterate.over` 的来源只剩两种——`ask`（**要弹窗问玩家**）和 `view` 里的 `entity[]` 字段（取决于预制体的视图声明有没有这一项）。

所以「每个我方单位 +1 攻击」这种效果，在 v1 要么逼作者弹一次选靶，要么依赖视图声明恰好给了列表。**这不是界面能绕过的**。

### 5.3 `script` 在 v1 是半残逃生舱

`inputs`／`outputs` 只是声明，没有值通道；正文只能用 `view`／`orcSelf`／`ctx`／`ct` 和**前面节点已建立**的绑定。所以它接不住 5.1／5.2 的缺口——不能拿它当兜底方案写进设计。

### 5.4 `choice` 一点就炸

`ChooseAsync` 运行期抛 `NotSupportedException`（等前端桥接 S10）。**建议**第一版 UI 里不放出 `choice`，或放出但标「需要交互桥接，当前会失败」。放出去不标＝作者必踩。

### 5.5 入前线／入支援线只能写脚本

`JoinFrontlineAsync`／`JoinSupportLineAsync` 在 EXCLUSIONS 的 **B 类（延后）**：返回 `ActionResult?`，补个 `[HandlerDslResult]` 就能进目录，本轮没补。这是「把单位塞进战场」的核心动作，**建议**向引擎侧催这一条——成本极低，收益很高。

## 7 对比用的样例任务

选这个任务，是因为它同时压到四个轴，而且**在当前契约下可表达**（避开了 5.1 的缺口）：

> **打出时**：选择一名敌方单位 → 对每个选中的单位：若我方点数 ≥ 5，造成 6 点伤害，否则造成 3 点伤害 → 抽 1 张牌。

```json
{
  "schemaVersion": 1,
  "actions": [
    { "op": "ask", "kind": "unit", "side": "enemy", "prompt": "选择一名敌方单位", "bind": "targets" },
    { "op": "iterate", "over": { "var": "targets" }, "as": "t", "actions": [
      { "op": "branch",
        "test": { "op": "ge", "args": [ { "read": { "of": "viewer", "path": "kredits" } }, { "lit": 5 } ] },
        "then": [ { "op": "damage", "target": { "var": "t" }, "amount": { "lit": 6 } } ],
        "else": [ { "op": "damage", "target": { "var": "t" }, "amount": { "lit": 3 } } ] },
      { "op": "draw", "count": { "lit": 1 } }
    ] }
  ]
}
```

交互草案：[`prototypes/inspector-compare-20261031.html`](prototypes/inspector-compare-20261031.html)（两种形态并排，同一份文档、同一份输出）。

### 9.1 外观：Scratch 的形状，本项目的配色（同日追加）

积木的**语义**由契约决定（树、数组顺序、无 exec 边）。形状借 Scratch——那套读法已被验证过
「一眼能看出这段逻辑怎么跑」；**颜色必须跟主题走**，不能照搬 Scratch 原版色板。

> Scratch 的 `#4c97ff`／`#ffab19`／`#ffbf00` 是给浅色儿童界面配的高饱和色。本项目是军绿底
> ＋黄铜＋羊皮纸的深色牌面（`MenuStyles`：`Panel #202925`、`Gold #d7af69`、`Ink #eee7d6`），
> 直接搬过来会炸眼、像另一套设计语言。所以：**形状照搬，色板重配。**

| 要素 | 做法 |
|---|---|
| 色板 | `BlockTheme` 从 `MenuStyles` 取值系：低饱和、偏暗的土色，亮度一律压在羊皮纸字之下 |
| 分组色 | 造成与消灭＝深血红 `#6f2f28`／控制流＝烧赭 `#95561f`／交互＝钢蓝 `#38536a`／手牌＝暗青 `#2f5a52`／战场＝暗橄榄 `#4f5c36`／资源＝黄铜 `#6b5c22`／属性＝暗紫 `#4d4066`／变量＝暗赭梅 `#5e3a48`／流程＝石板灰 `#3c4850`／高级＝中性 `#3a403c` |
| 形状 | `BlockShape._Draw()`：圆角实心 ＋ 上缘缺口 ＋ 下缘凸榫；列表间距＝凸榫探出量，榫卯正好咬合；外描 1px 半透明黑把块从暗底上托起来 |
| 帽块 | 黄铜 `#c8a35c` ＋ 近黑褐字——主题里唯一的高光色，一眼看出「这段逻辑挂在哪」 |
| C 形块 | 容器块＝头 ＋ 左侧竖脊 ＋ 脚；头的底角与脚的顶角取 0，接缝才不掐腰 |
| 输入 | **做旧纸张**芯片（`#d6cfba`／深褐字），枚举带 `▾`；算子芯片旁按 `( arg , arg )` 展开参数 |
| 深字/白字 | `InkFor(luma)`：深色块用羊皮纸 `Ink`，浅色块（只有帽块）用 `#2a2318`；次级文字用 `MutedInkFor`，不用灰色 |
| 错误块 | `#a8402f`：比任何分组色都扎眼，但仍在土色系里 |

两条配色经验：
1. **两组最常出现的块必须拉开**。「造成与消灭」和「控制流」都在红橙区间，最初一个 `#6e352c`
   一个 `#8c4f26`，缩到实际尺寸就分不清了。最后压成「偏冷深红 vs 提亮烧赭」，靠色相＋亮度双重区分。
2. **芯片只能比块亮，但不能纯白**。深色块上纯白芯片太跳；做旧纸张既够亮又不脱离主题。

**尺寸取「贴合内容」而非撑满**：Scratch 的块宽由内容决定，撑满会让「一块积木＝一步动作」这个读法失效。

> 截图坑：`Show()` 会起 0.20s 的入场淡入（`Main.MenuMotion`），只等两帧会截到 alpha≈0.55 的半透明图，
> 整张偏暗、颜色看着像配错了。`CaptureHdsl` 已改成先等 0.32s 再截。

**还没做的**（按重要性）：

1. **写回**：现在只产出 DSL 文本，没有接 `AssetEditor.Commit`，也没有 `.moding.json` 草案；
   引擎检出合并前这条路径编译不过（见 §6 前置条件）。
2. **目录来源**：用镜像快照，未接 `HandlerCatalogFacade`；接上后 `catalogRevision` 变了要重拉。
3. **视图字段**：用 3 个假字段（Card／Defense／Units），未接 `DescribePrefab`。
4. **`script` 节点**（可加但无值通道）、**多输出 `bind` 的对象形态**（界面只做单输出）。
5. **只读结构总览**（§3 第 3 条）：未做。

## 10 工具箱与去术语（2026-11-01 追加）

这一轮只改界面层，契约与校验器没动。三件事：**所有节点进工具箱**、**界面说人话**、**`choice` 真的能画**。

### 10.1 为什么从「弹出调色板」改成「常驻左栏」

旧做法是点「＋ 添加积木」弹一个 `PopupMenu`。节点涨到 **37** 个之后这条路断了：

- 37 项塞进一个 popup 要滚三屏，分组只能靠 `— 造成与消灭 —` 这种禁用项冒充标题；
- popup 挡住画布，选的时候看不见自己要插在哪一段；
- 每插一块都要重开一次菜单，重复劳动。

改成常驻左栏（`BuildToolbox`，286px）后：分组有色块＋一句说明、能搜、插入位置单独一行写着，
**点一块就插进去**，连点几块就是从上往下的顺序（数组顺序即执行顺序，正好对上）。

| 细节 | 做法 | 为什么 |
|---|---|---|
| 插入位置 | 画布上每个「＋ 添加积木」只负责**选中位置**，选中后自己变成「↓ 就插在这儿」 | 一个动作只做一件事；位置和目标块分开显示，不用记 |
| 位置文字 | `RenderArray(..., where)` 传人话（「整段的最后」「如果 的『不然』里」「选项2 里面」） | 工具箱那行要读得懂，不能写 `actions[0].then` |
| 位置失效 | 撤销／重做／换文档时 `ResetInsertTarget()` | 这三处会把 `_doc` 换成克隆体，旧目标指向已不在画面上的列表——插进去像「点了没反应」 |
| 插入后 | 两帧后 `EnsureControlVisible`（`Reveal`） | 新块常落在折叠区外。**必须等两帧**：第一帧容器才按新块高度重排 |
| 分组色脊 | 每行左侧 3px 分组色，hover 换黄铜描边 | 一行扫过去就能认出这组是什么颜色，不用读字 |
| 组标题 | 组名 ＋ 下一行小字说明 | 一行放不下（最长 11 字），硬切像掉字、省略号又看不清——两行最省事 |

**为什么行是横条、不是小积木**：形状语言留在画布上。工具箱要的是**可扫读的清单**，
每行都做成榫卯积木会让人误以为它们之间有顺序关系。

### 10.2 去术语：改的是词，不是概念

原则写进 `HandlerVocabulary` 的类注释：**作者是来设计卡牌的，不是来读规范的**。

| 原来 | 现在 | 说明 |
|---|---|---|
| 绑定 / 表达式 / 引脚 | 起个名 / 值 / 格子 | 「引脚」是电路板的词，这里没有引脚 |
| 顺序 / 重复 N 次 / 当…时 | （合并）重复几次 / 只要…就一直做 | `sequence` 保留，标题「顺序」 |
| 让玩家选择 / 询问目标 | 让玩家选一个 / 让玩家挑目标 | |
| 写入属性 / 重跑光环 / 停止 / 中断 | 改卡片上的属性 / 重新计算加成 / 就此停下 / 打断后面所有 | |
| 输出 .hdsl.json / 本地校验 / 通过 / N 个节点 | 生成的内容 / 检查结果 / 没问题 / N 块 | 右栏标题 |
| `le` `ge` `count` … | 小于或等于 / 大于或等于 / 有几个 | `OperatorLabel`；算子表封闭（SPEC §5），可穷举 |
| `read.path` 的 `attack` `kredits` | 攻击力 / 点数 | `ReadableLabel` |
| 视图字段 `Defense` | 防御力 | `ViewFieldLabel`；**只翻显示**，存进文档的仍是原名（SPEC §0.4 禁别名） |
| `list<entity>` `number` | 一组实体 / 数字 | `TypeLabel` |
| 错误码 `pin-missing` | 「还有地方没填」 | `IssueTitle`；**原始码留在 tooltip**，排查的人仍拿得到 |
| `actions[0].value.read.path` | 「第1块 · 值 · 读取 · 属性」 | `FriendlyPath`；原始路径也留在 tooltip |

两处**故意保留英文**：积木的 tooltip 里仍写 `op` 名与契约路径；错误行 tooltip 里仍写错误码。
界面是给作者的，tooltip 是给排查的人的——两边不能都满足时，作者优先、排查的人退到 tooltip。

### 10.3 `choice` 终于能画了

契约里 `options` 是 `[{label, actions}]`，**不是**动作数组（SPEC §3），所以不能塞进 `Bodies` 当普通子体走。
数据侧早就有 `HandlerOption`，界面这一轮补上 `RenderChoiceArms`：

- 每条臂＝「选项 N ＋ 一句话芯片 ＋ ✕」＋ 自己的动作列表 ＋ 自己的「＋ 添加积木」；
- 臂与臂之间一条 14% 透明度的细线（**必须直接挂到 `inner`**，套 `MarginContainer(ShrinkBegin)` 会被压成 0 宽看不见）；
- 底部「＋ 添加选项」。

新插入的 `choice` 默认带**一个空文字的选项**，故意留空：选项文字是给玩家看的话，不能替作者编。
校验器会报 `pin-missing @options[0].label` → 界面显示「还有地方没填 · 第N块 · 选项1 · 选项文字」，
正好把作者按到那句话上。

> 顺带修掉的两处「插进去就报错」：`damage` 默认不再猜 `target = ‹t›`（猜错会报成「名字用错了」，
> 比留空报「还有地方没填」难懂）；`ask`／`unitsOf` 的 `side` 按契约写成值引脚带取值集。

### 10.4 验证

- `dotnet build`：0 错误；`HandlerDslEditorTests` **29/29**。
- 全量 `Kards.Ui.Tests`：741 通过 / 2 失败，两条（`CrossEffectTargetTests`、`MatchDebugTests`）
  在干净检出 `bac0298` 上**同样失败**，与本次改动无关（引擎侧漂移）。
- 截图 `artifacts/hdsl-editor.png`：37 块工具箱、5 块样例、检查结果「没问题」。
- 插入路径单独冒烟：程序化插入 `draw` ＋ `choice` 后块数 5→7、画布自动滚到新块、新 `choice` 如预期报
  「还有地方没填」。（临时钩子只加在运行副本，未进仓库。）

## 11 能力分区：把「现在跑不起来」标出来（2026-11-02 追加）

引擎 `299d93d` 加了 SPEC §12.11，要求目录对每个可拖的东西给出 `alpha`／`preview` 分区。
我们上一版正好违反了它——`choice` 被当成普通积木摆在工具箱里，而它运行期**无条件抛**
（`ChooseAsync` 在排除清单里，只由生成码调用）。这是「能画、能校验、能生成、一跑就炸」的典型。

### 11.1 判据是登记，不是探针

这一点跟 DIY 那边的 `DiyOpCatalog` 恰好相反：那边每个动作拿默认声明走一遍
`DesktopNativeLowering.Lower`，抛异常就进「预览」。对 handler DSL 不能这么干——`choice` 编译能过，
探针会把它判成 alpha，**比不标更糟**。所以：

- 节点级：`HandlerNodeSpec.Stage`／`Problem`，缺省 alpha，不写进快照
- 内建 op：`HandlerCatalog.BuiltInOps` 表，顺序照抄契约（`sequence`…`script` 十个）
- `StageOf`／`ProblemOf`：先看节点标注，再看内建表，都没有＝alpha

今天**只有 `choice` 是 preview**，零个扫描节点带 `[HandlerDslPreview]`。测试里那条
`choice是唯一的预览态节点` 就是「行为测试背书」——引擎接通 S10 后它会先红，逼人回来改。

### 11.2 界面怎么表现（不裁剪）

| 位置 | 做法 |
|---|---|
| 工具箱 | 组内 alpha 在前、preview 在后（稳定排序，同档保持目录序）；行压暗到 0.22 alpha、右侧「还不能用」角标、tooltip 摆原因。**照常可点** |
| 画布块 | 标题后加一个金色「还不能用」小标，tooltip 同原因——作者是在这块积木上做决定，不能只在右栏提一句 |
| 检查结果 | 一条金色警告「有 N 块现在还跑不起来」＋每个 op 一行原因；右上角计数变「N 块跑不起来」（金色，不是红色） |

**不新增错误码**：13 个码是封闭的，预览态是「能存但跑不了」的事实，不是校验错误。
契约也明说「允许先搭图，保存前再拦」——拦截留给将来接 Commit 的那条链。
