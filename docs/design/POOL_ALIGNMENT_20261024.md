# 卡池对齐方案（pool-v1，2026-10-24）

> 目标：让"两边卡池不一样"在**开局前**变成一句人话，而不是开局炸或对面卡图空白。
> 上游已有约定（`docs/服务器管理器-长期生命周期/前端交接-协议变更与API参考.md` §6.1）：
> `room.info` 应含 `pool: {generation, fingerprint, packPolicy}`。本方案**沿用该字段名**，不另造协议。

---

## 0. 先把"对齐"拆成三件事

| 层 | 含义 | 不一致的后果 |
|---|---|---|
| 身份对齐 | 同一个 `(kind,id,guid,version)` | 依赖解析失败、包被当成两个 |
| 内容对齐 | 同 version 的**字节级**同一份 | 同名卡不同数值的静默分裂（DIY 就地改包最常见） |
| 装载对齐 | 服务端只有一份权威目录 | 结算与画面不同源 |

只有第三件事影响公平性，前两件只影响体验。**设计必须让三者都可观测**。

## 2. 设计原则（硬约束，不可协商）

1. **声明不作数**：任何客户端的 `packages` 只用于"对账展示"和"是否放行"，**绝不**进入 `PackDirectories`。服务端只从房主磁盘装载。
2. **默认只下行，上行必须显式开启**：资产分发默认只有 房主 → 客人。客人 → 房主 等价于"载入对方提供的可执行内容"，必须由房主手动开，且默认关（§3.6）。
3. **拉来的东西不属于玩家**：一律进会话暂存，不进 `<packsRoot>`、不进构筑、不进单机；"存下来"是显式动作（§3.5）。
4. **不信任传输**：每个文件、每个分块落地前按 `sha256` 校验；校验失败的包**整包丢弃**，不留半包。
5. **指纹只用于人读与放行判定，不是安全边界**：真正的边界是逐文件 sha256（16 位指纹有碰撞可能，明确写死这一点的边界）。
6. **零成本默认路径**：两边一致时不产生任何额外流量、不弹任何窗、不多一次点击。

## 3. 五层模型

### L0 · 摘要（本机，注册时算一次）

```
digest(packDir) = SHA256( 按相对路径排序的每一行: "relPath\0size\0sha256(content)\n" )
排除: .cache/ obj/ bin/ *.tmp
poolFingerprint = SHA256( 按 id 排序的每一行: "id\0version\0guid\0digest\n" )[0..16]
```

- 缓存到 `<packsRoot>/.digest.json`，以"目录内最新 mtime + 文件数"为失效键；未变则不重算。
- **卡图不在包目录里**（已核实：`proto/data/kards/packs/builtin` 有 214 个 json、0 个 png；图走发行包 `asset-manifest.json`）。所以 digest 只覆盖**规则**；**官方卡图的一致性由 `buildId`（`.orcksd-build.json`）保障**，两条线一起看。

### L1 · 声明（attach）

- 客人 `session.attach` 带上本机**已注册**的包集合（不是"打算用的"）。
- 服务端把每座声明存进 room（`slot.Packages` 结构已存在）。
- 声明里带 `digest`，因为 `version` 相同内容不同的情况真实存在。

### L2 · 对账（room.info，开局前一直可见）

服务端返回（补上上游 §6.1 的 `pool` 段）：

```json
"pool": {
  "generation": 4,
  "fingerprint": "9f2c1a7b3d4e5f60",
  "packPolicy": "loaded",
  "buildId": "12197E56A2F5",
  "packages": [
    {"packageId":"pack/builtin","version":"1.0.0","guid":"…","digest":"a3f1…","bytes":1843200}
  ]
}
```

每座只回**自己**的 `declaredFingerprint`（沿用 `Room.Snapshot` 的"对手声明永不可见"口径）。

客户端本地算 diff，得到四类结果：

| 结果 | 判定 | 呈现 |
|---|---|---|
| `aligned` | fingerprint 相同且 buildId 相同 | 绿 · `卡池 9f2c1a7b · 已对齐` |
| `extra` | 我有房主没有 | 黄 · 不影响对局，可忽略 |
| `missing` | 房主有我没有 | 红 · 列出包名与字节数，给"取回"按钮 |
| `mismatch` | 同 id 不同 version **或**同 version 不同 digest | 红 · 明确写"同版本内容不一致"，不静默 |

### L3 · 补取（新协议面，**双向、会话级**，不入库）

两个新工具，受 `pool-v1` capability 门控：

```
pool.manifest { packageId } -> { digest, totalBytes, files:[{path,size,sha256}] }
pool.fetch    { packageId, path, offset, length } -> { data: <brotli 块, base64>, sha256 }
```

- 块 256 KB，复用发行体系已有的 content-addressed + brotli 思路（`tools/OfflineUpdate` 的 `blocks/*.br`）。
- 落地目录：**会话级暂存**，见 §3.5。过程态写 `<pkgId>.partial/`，全文件校验通过后原子 rename。
- 权限：仅 `controller`、仅 `state=lobby` 可调；按连接限速（默认 4 MB/s）；`AllowHostPacks`（默认开）/ `AllowGuestPacks`（**默认关**，理由见 §3.6）。
- 断点续传：按 `(path, sha256)` 记已完成项，重连继续。

#### 3.5 会话级暂存（不入库）

```
user://net-assets/<sessionId>/packs/<packageId>/     ← 仅本房间会话内注册
user://net-assets/blocks/<sha256>.br                 ← 跨会话内容块缓存（LRU，可清）
```

- `sessionId = roomId + pool.generation`：房主重载包 → 代次变 → 视为新会话，旧暂存作废。
- **注册方式**：只作为 `SpawnRequest.PackDirectories` 的额外一项。**不写** `<packsRoot>`、**不进** `.digest.json`、**不进**构筑/单机/工坊的可见卡池。
- **"不入库"是天生成立的**：`ServerManager.Assets` 是**实例级**（`ServerManager.cs:33`），而 `ServerLauncher.StartAsync` 每次建房都 `new ServerManager(...)`、关房 `DisposeAsync`（`:283`）。所以只要不进磁盘卡池，进程退出即彻底消失，**不需要额外的卸载逻辑**。
- 生命周期：离开房间/终局后保留 **24h**（断线重连要用），过期清理。玩家想长期保留 → 显式点"存进卡池"，才搬进 `<packsRoot>`。
- 收益：① 玩家卡池永不被污染 ② 不用为"拉来的包"造一个稳定安装根 ③ 语义正确——你没装这个包，就不该能在构筑里选它的卡。
- 代价：换房间若换了对手，同一包可能要重拉。用 `blocks/` 缓存吸收大部分重复流量（块按 sha256 复用，天然去重）。

#### 3.6 双向拉取的不对称（必须默认不对称）

| 方向 | 风险 | 默认 |
|---|---|---|
| 房主 → 客人 | 低。房主本来就是这个对局的权威，客人的客户端本来就要演房主算出来的结果 | **开** |
| 客人 → 房主 | **高。包的 `csx` 效果脚本由服务端 `NativeScriptHost` 在房主机器上执行**——等于让对手往你机器里塞可执行代码 | **关** |

所以"相互拉取"要落地成两个独立开关，不能是一个。房主想接带自有卡组的朋友时手动开 `AllowGuestPacks`，此时 UI 必须写明"将载入对方提供的效果脚本"。

### L4 · 开局门（match.start）

```
两座声明 fingerprint == 房主 pool.fingerprint ？
  否 -> pool-mismatch + 结构化 diff（哪座、缺哪个包、缺多少字节），房间留在大厅
  是 -> 用房主磁盘目录 Plan(host 声明, guest 声明)   ← 终于变成真的并集判定了
       -> 装载 -> 开局
```

同时把卡组校验**前移到 claim**（复用现成的 `DeckRulesValidator`），失败信息随 `room.info` 的 `seats[].deck` 回到客人自己那里。

## 4. 安全边界（写死，别在实现时"顺手放宽"）

| 攻击面 | 处理 |
|---|---|
| 客人声称拥有某包但并没有 | 声明只影响"是否放行"，服务端不从客人处装载 → 无效 |
| 客人伪造 `digest` 骗过开局门 | 开局门只决定"能不能开"，装载仍走房主目录；伪造只会让自己卡图空白 |
| 传输中被改字节 | 每块 + 每文件 sha256，失败整包丢弃 |
| 客人狂拉包耗房主带宽 | 限速 + 单连接串行 + `lobby` 状态门控 |
| 客人本地改包改数值 | 结算在服务端，本地改只改自己看到的画面 → 影响不了对手 |
| **客人借"互相拉取"往房主机器塞 csx** | `AllowGuestPacks` 默认关；开启时必须显示"将载入对方提供的效果脚本"。拉来的包只进会话暂存，会话结束即消失 |
| 暂存目录被当成常驻卡池 | 暂存根与 `<packsRoot>` 物理隔离，且不写 `.digest.json`；"存进卡池"必须是显式动作 |

## 5. 决策矩阵（缺包时到底怎么办）

| 情况 | 默认动作 | 理由 |
|---|---|---|
| 客人缺 **官方** 包 | 不可能（同一个发行包），若出现 → `buildId` 不同，提示"版本不一致，请更新到 X" | 官方包是发行物，不是分发物 |
| 客人缺 **工坊/DIY** 包 | 提示 + 一键拉到**会话暂存**（不入库） | 去中心化分发，不依赖 CDN；但装不装由玩家决定 |
| 房主缺客人带的包 | **默认拒绝开局**并点名；房主手动开 `AllowGuestPacks` 才拉取 | 拉进来就要执行对方写的 csx |
| 客人多包 | 只提示，不阻断 | 多的包不参与本局并集 |
| 同 version 不同 digest | **阻断**，写明是哪个包、哪个文件不同 | 静默分裂比报错更贵 |
| 老客户端（无 `pool-v1`） | 退化为"fingerprint 不等则拒绝开局"，不发补丁 | 不做降级分发，避免两条代码路径 |

| 期 | 内容 | 工作量 | 验收 |
|---|---|---|---|
| **P0 · 通电** | ①客人声明填真值 ②`room.info` 补 `pool` 段 ③UI 读 `pool.fingerprint`、删掉硬编码 `"loaded"` ④卡组校验前移到 claim | 0.5 天 | 连接详情显示真指纹；客人带非法卡组在**占座时**就看到点名 |
| **P1 · 看得见** | digest 计算 + 缓存 + 四类 diff + 三色 UI | 1 天 | 拆掉一个包 → 房间立刻红字"缺 1 包：X（1.8 MB）"，且不阻塞其余流程 |
| **P2 · 能自愈** | 会话暂存根 + `pool.manifest`/`pool.fetch` + 落地校验 + 块缓存 + 续传 + 24h TTL | 2 天 | 两台机器：A 有工坊包、B 没有 → B 一键拉到暂存 → 指纹相等 → 开局 → B 能看到该包的卡图与文本；**B 的构筑界面里依然没有这个包**（不入库） |
| **P3 · DIY 闭环** | 去掉房间对 `diy/` 的拒绝；`AllowGuestPacks` 开关与风险文案 | 1 天 | 自建卡包可跨机对战（发行说明里唯一还写着"不支持"的那条） |

**P0 就能把"发版事故级"的问题消掉**：现在这套是"有架子没通电"，P0 之后至少每一处不一致都有名字。

## 7. 反例（明确不做）

- ❌ 锁步 / 帧同步对卡池：卡池是开局前的一次性事实，不需要逐帧对齐。
- ❌ 客人之间 P2P 互传资产：会引入第三套一致性模型，收益不抵复杂度。
- ❌ 把 `pck` 纳入 digest：1.17 GB 每次开房算一遍，且用户装的是同一个发行包，没有信息量。
- ❌ 自动"降级兼容"（缺包时用占位卡替代）：会让玩家以为存在一张其实不存在的卡，比分发更糟。

---

## 8. 一句话总结

**声明（客人说真话）→ 摘要（字节级身份）→ 对账（四类结果）→ 补取（双向、会话级、不入库）→ 开局门（指纹相等才放行）。**
公平性只依赖"服务端只从房主目录装载"这一条，其余全是为了让不一致**在开局前就有一个名字**。
"不入库"让这条设计不用在玩家磁盘上留下任何痕迹——拉来的包属于**这一局**，不属于玩家。
