# Inspector 首批重构：能力基线与组合编辑原型

日期：2026-10-20。对应实施方案 P0／P1，并先落地一部分文档事务基础；不代表 P2～P5 全部完成。

## 已落地的操作

入口仍是 DIY 卡牌 → 效果搭建 → 图形搭建。

- 主页面先设置发生时机和动作；效果前提可选，不要求先理解整棵结构树。
- 对象范围、查询计数、属性读取、比较、全部／任一／取反和计算使用同一个组合编辑窗口。每次只展开当前层，保留返回路径及整体预览。
- 普通数值仍可直接修改；需要复杂取值时打开组合编辑。动作中的条件、效果前提和查询筛选复用同一编辑器，但保留各自语义位置。
- 修改先进入独立副本；“应用修改”才提交。取消、关闭和 Escape 不写入源文档。一次应用对应一次撤销，修改来源已变化时拒绝覆盖。
- 切换组合类型后，应用前切回可恢复该类型此前的参数和扩展字段。未填写的值与空条件组不能应用，不生成隐含的 `1 >= 1`。
- 对已知类型提供输入检查：数字不能使用“包含”，数值不能与文字作大小比较，算式不能把文字自动当成零。
- 保留完整声明、未知字段和原有高级入口；旧条件／取值仍提供兼容参数入口。现有 161 个动作的打开检查无损，不等于它们全部已被原生引擎支持。

实现没有增加特定卡牌、兵种组合或完整触发句子的专属编辑器。新增逻辑集中在编辑事务、独立副本、结构组合和填写检查，没有新增玩法求值器。

## 后续接入边界

本轮是可操作原型与编辑状态重构，不是全量后端契约迁移。当前组合视图仍适配已有 Desktop 声明；尚未切换既有 V8 文本解析入口，尚未添加第二套文本解释器。

1. 后端仍缺按时机导出的上下文、完整参数类型和合法组合目录。事件引用不自动补造，旧引用保留；目前的类型检查仅覆盖已知结构，后端编译仍是最终检查。
2. 效果级前提与动作分支保持不同位置；后端不接受的声明继续显示仅草稿，不偷偷移动条件来换取编译通过。
3. 跨回合记忆表达式和原有 DIY 中文计数器不是同一套声明。原中文计数器入口保留，统一引用目录仍需后续适配。
4. 后端选靶空格缺陷、反制语义及定位诊断需明确解决，再进入正式文本链切换。双向文字同步、旧数据迁移、全部原生触发资产开放尚未完成。
