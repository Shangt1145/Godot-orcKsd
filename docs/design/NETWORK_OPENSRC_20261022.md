# 联机网络层：从 Radmin 切换至开源组网（2026-10-22）

## 1. 背景与动机

`Radmin VPN` 是闭源商业软件。用户基于开源精神决定把联机网络层从 Radmin 换成开源方案。

网络层的职责始终不变：**给分散在各地的玩家搭一个"虚拟局域网"**，让房主拉起的 `Orc.Server` 能被其他玩家用 TCP/JSON-RPC 访问。对游戏而言，对方就是"局域网里的另一台机器"——这就是本方案能替代中央服务器的根本原因（"免费房间服务器"）。

切换的本质：**网络层与具体组网软件解耦**。玩家装机哪款软件是运维动作，不是代码改动。

## 2. 关键约束：自动发现依赖广播/组播透传

房间发现（`proto/bridge/Kards.Ui.OrcBridge/RoomDiscovery.cs`）走：

- 房主每 2 秒向 **`255.255.255.255` 全网广播 + `127.255.255.255` 环回** 发一条 JSON 宣告（`DiscoveryPayload{v, roomId, port, seats, name}`）。
- 客人 `UdpClient` 监听 **UDP 47188**（`RoomDiscovery.DefaultPort`），按 `roomId` 去重、7 秒超时剔除。
- 宣告里**不带 IP**，接收方用 `RemoteEndPoint.Address` 当房主地址。

这条链路能自动工作，**前提是底层虚拟局域网透传广播/组播**。选型第一判据就是它——不透传，自动发现直接失效，退化成手动填 `IP:端口`。

> 为什么用广播而非组播：广播地址 `255.255.255.255` 与子网掩码无关，任何虚拟网卡都发得出去；组播地址虽也行，但早期在 Radmin 下广播最稳，沿用至今。

## 3. 开源候选对比

| 候选 | 开源纯度 | 透传广播/组播 | 自动发现 | 运维成本 | 评价 |
|---|---|---|---|---|---|
| **ZeroTier One** | 客户端 + 控制器可自托管（BSL / 源可见） | ✅ 虚拟以太网段，广播组播都通 | ✅ 无缝保留 | 低（装软件 + 加网络 ID） | **默认推荐**，社区最大 |
| **n2n** | GPLv3，纯开源 | ✅ 同左 | ✅ 无缝保留 | 中（需自己跑一个 supernode） | 最对得起开源精神，零厂商依赖 |
| Tailscale / Headscale | Headscale 全开源、Tailscale 源可见 | ❌ 纯 L3，无广播域 | ❌ 失效 | 低（Tailscale）/ 中（Headscale 自托管） | **避坑**：除非接受手填 IP |
| Netbird | 全开源（WireGuard 管理面） | ❌ 同上 | ❌ 失效 | 中 | 同上，UX 好但不透传广播 |

> WireGuard 系（Tailscale/Headscale/Netbird）是优秀的 L3 隧道，但**没有广播域**，`255.255.255.255` 宣告发不出去。它们的 mDNS / MagicDNS 也不走我们的裸 UDP 广播发现。除非你愿意放弃自动发现、只用手填地址，否则别选这一支。

## 4. 推荐结论

- **默认 ZeroTier One**：最像 Hamachi/Radmin 的平替，广播透传，自动发现无缝保留；控制器可自托管（`ztncui`）做到零厂商依赖。
- **纯开源取向选 n2n**：GPLv3，自己跑一个 supernode（小 VPS 或某玩家端口映射），完全无第三方。客户端偏命令行 / 社区构建，运维稍多。
- 二者都透传广播，现有 `RoomDiscovery` 一行不用改。

## 5. 代码解耦（已落地，2026-10-22）

唯一与 Radmin 真耦合的是地址展示优先级，已改为"虚拟局域网无关"：

- `proto/ui/screens/RoomScreen.cs` 的 `FormatAddresses` 原写死 `address.StartsWith("26.")`（Radmin 网段）优先。
  改为新增 `AddressPriority(string)` 通用判定：
  - `0` = 虚拟局域网段：`26.` / `28.` / `29.` / `30.`（Radmin + ZeroTier 常用段）
  - `1` = 其它私有网段：`10.` / `172.` / `192.168.`
  - `2` = 公网
  - `9` = 链路本地 `169.254.` / 环回 `127.`（不可用，永远垫底）
  - 新增组网软件只需在 `0` 档加网段即可。
- `RoomDiscovery.cs` 广播逻辑**无需改动**（只认 `255.255.255.255`，不认具体网卡）。
- UI 文案去 Radmin 化：
  - `SetupScreen.cs` / `RoomScreen.cs` 的"Radmin 亦可" → "虚拟局域网（ZeroTier / n2n 等）亦可"。
  - `RoomScreen.JoinAsync` 手填示例 `26.109.28.81:4717` → `10.147.20.5:4717`。
  - `RoomDiscovery.cs` 顶部注释去 Radmin 化。

> n2n 默认用 `10.x`，与家庭局域网同档（排名 `1`）。自动发现仍靠广播走通；手动分享地址时用户在界面上自己挑那个虚拟网卡地址即可。

## 6. 部署（运维，不是代码）

1. 所有玩家安装**同一款**组网软件（ZeroTier / n2n）。
2. 加入**同一个**虚拟网络（ZeroTier 网络 ID；n2n 同一 supernode + 网络名）。
3. 房主进作战房间起服，客人在"局域网房间"列表看到（或手填 `IP:端口`）→ 加入。流程与原来完全一致。

> 这一步等价于以前"让群友装 Radmin 进同一个公开网络"，只是换了软件。

## 7. 验证
