# 对战界面迁移到 3D：实施设计

日期：2026-11-05。状态：首版共享 3D 战场已接入，底部有本轮实现与验证记录。目标是对齐原版 KARDS 的桌面空间观感，并支持真实卡牌起飞、空间攻击和交互桌饰；不据此声称已核实原版内部实现。

## 已确认现状

- `BattleScreen` 是 Control，桌面是一张 TextureRect；战场逻辑布局使用 1280×720 坐标。
- `BattleCard` 是 Control，起飞、倾斜和离桌主要由 2D 绘制、偏移及缩放表现。
- `OriginalPropView` 已加载真实 GLB，但每件桌饰使用独立 SubViewport、相机和灯光，最终叠到 2D 桌面；不能共享场景遮挡、光照和投影。
- 部署空隙、拖拽、攻击目标与动画多处直接读取 Control 的位置和尺寸，迁移必须同时处理交互与动画坐标。

## 目标结构

共享 3D 世界承载桌面、战场单位、总部、牌堆、空间特效和桌饰；透视相机提供统一投影。资源数、菜单、日志、详情与选择弹窗保留为屏幕 UI。手牌呈现与拖出上桌的衔接需要单独设计，不能因桌面迁移而直接删掉现有扇形手牌交互。

卡牌使用有厚度的薄网格，正背面材质、位置和姿态独立。现有卡面绘制可作为纹理生成来源：纹理仍是平面的，但承载它的是可旋转、投影并参与遮挡的独立 3D 对象。避免将整张旧战场贴在一个平面上充当迁移成果。卡面渲染应缓存并按需更新，避免为每张牌持续全量刷新高分辨率视口。

规则仍使用已有投影、命令与合法候选。3D 表现实体按 Uid 绑定，不能用物理碰撞替代引擎规则。固定行列／阵型布局映射为世界坐标，鼠标和触摸经相机射线完成单位、桌饰与桌面的命中；部署提交引擎候选 ID。

## 攻击与桌饰

空军演出明确区分起飞、接近／攻击、受击和归位；高度、俯仰、侧倾和影子随真实姿态变化。飞行中的命中与特效挂在动态锚点，不能继续引用起飞前的屏幕中心。具体动作依据原版实机参考再定，不把“起飞”直接解释成飞到敌人位置碰撞。

桌饰复用已有模型加载能力，将模型实例放入共享世界，保留尺寸、朝向、动画和交互锚点；桌饰点击与战斗选靶分别路由。碰撞区域不得遮住正常卡牌操作，模型资源有动画时再接对应动作，静态模型不伪称可还原全部交互。

所有动画继续遵守当前事件顺序、取消和终局语义。重开／离开／投影替换要清除旧演出，并恢复最终权威状态；减弱动效保留行为结果与关键反馈。

## 实施顺序与验收

1. **3D 场景和坐标基础**：相机、桌面、光照、独立卡牌和共享桌饰。核对常见分辨率、桌面与移动端的投影和可读性。
2. **真实对局交互**：以真实投影摆放双方单位与总部，接通选中、悬停、拖拽、部署空隙、移动、攻击与取消；验证屏幕命中和引擎候选一致。
3. **完整表现迁移**：抽牌、出牌、换牌、目标选择、起飞攻击、受击死亡、牌堆和终局。每条表现验证中断与重开，不保留混用坐标导致的漂移。
4. **桌饰与视觉校准**：模型位置、遮挡、光照、交互、镜头、材质与空间特效；以实机参考校准观感。
5. **回归与发行**：单机和双端对战、隐藏信息、触摸、宽高比、减弱动效和性能测试；验证导出产物后切换默认战场。

第一阶段只是迁移基础，不能称完整改造已完成。正式切换需覆盖现有可操作流程，不以截图或 3D 场景启动成功代替对战验收。

## 主要实现入口

`BattleScreen.cs`、`BattleScreen.TableMotion.cs`、`BattleScreen.Presentation.cs`、`BattleScreen.Cosmetics.cs`、`BattleCard.cs`、`BattleCombat.cs`、`OriginalPropView.cs`。应先提取表现姿态、锚点和命中接口，再逐步替换对 Control 的直接位置访问。

首轮需实测相机下文字清晰度、透明纹理阴影和 Android Compatibility 渲染表现；当前使用的桌面背景已经包含透视与装饰，不能不经处理直接当平铺桌面材质，否则会重复透视和烘焙阴影。

## 2026-11-05 实施记录

- 新增 `BattleWorld3D`：共享 SubViewport／World3D、透视相机、灯光、桌面、独立卡牌网格和桌饰实例。战场、总部、手牌、背面牌和牌堆均有独立 3D 承载；详情与按钮保留屏幕 UI。
- 复用卡面绘制作为按需更新的双倍分辨率纹理。旧 Control 保留逻辑布局和交互状态，其主画面绘制关闭，射线命中回到既有逻辑坐标；不是把整张 2D 战场贴上平面。
- 卡牌离桌高度、倾斜和影子进入真实空间。瞄准线及战斗命中使用投影锚点；爆炸、弹道等现有屏幕特效仍为 2D，并未全部换为 3D 粒子。
- 桌饰原模型加入同一世界。资源自带动画时可点击播放；没有动画的模型保持静态，尚未逐项还原原版桌饰交互。默认桌面使用原背景中央纯木纹区域的运行时裁切贴图，不复用烘焙物件。
- 修复重绘／重开时手牌悬停 Tween 的回调访问已释放卡牌的问题；相机初始化在入树前设置局部 Basis，避免 LookAt 失效。
- 设置 → 演出新增“倾斜战场视角”开关，默认关闭，使用相机垂直朝向桌面的平直俯视；开启后使用倾斜透视。偏好写入 `user://fx_speed.cfg` 的 `battle/tilted_view`，切换即时更新卡牌投影与桌饰锚点。两种模式共用真实 3D 世界，均保留起飞高度。
- 前线标示移至占领方朝向对手的一侧，三角齿指向对手。指向指令按下后冻结手牌姿态，只拖出箭头，松手向目标提交；悬停动画不能改动持有中的指令。声明式效果的首个打出目标从已编译声明纯读取，不通过执行选择器预查询。
- 部署演出的临时卡牌从大卡面、敌方翻面到场上形态全程进入共享 3D 世界；详情面板仍为屏幕 UI。卡面缓存同时追踪显示模式和尺寸，避免切换场上形态时沿用旧纹理。
- 临时演出与牌堆等 Ignore 输入对象不参与鼠标逻辑坐标映射，避免动画中的卡牌干扰下一次部署落点。

### 验证

- `dotnet build Kards.Ui.csproj --no-restore --nologo` 成功；3 个现有 nullable 警告。
- 新入口 `--verify-battle-3d`：真实窗口渲染，检查投影、射线、实际 GUI 点击、1100×720 缩放命中、手牌拖拽部署、GLB 模型、离桌高度、重开清理及真实飞机演出归位。
- 视角验证覆盖设置按钮保存／重新读取、两种镜头的射线命中与离桌高度，并输出平直／倾斜截图。
- 新增双方三档部署的逐帧共享 3D 连续性检查；`--verify-target-drag` 增加平直／倾斜两种视角下持有指令姿态不变与取消后重试检查。`--verify-deployment` 通过 36 组视觉检查和演出期间连续输入回归。
- `DesktopOrderPreviewTests` 使用真实引擎验证显式声明指令：重复预览不出牌、不改变数值、不弹选靶请求；带拖拽目标提交后只结算一次。
- 常规脚本入口：`tools/run.ps1 -VerifyBattle3D`；会同步到短路径工作副本、构建并运行上述验证。
- 默认 Forward+／Vulkan 与 Compatibility／OpenGL 两条渲染路径验证。日志和截图：`artifacts/battle-3d/`。
- 现有 `--verify-action-portals` 通过：14 组真实引擎部署空隙、飞行抽牌接管、敌方演出输入锁。并通过 `TABLE_MOTION_VERIFY_OK`（含多目标单次起飞与归位、余效清理）。

仍需后续完成：原版镜头／布局／光照的精确校准、各类桌饰动画映射、全部粒子的空间化，以及 Android 真机性能与双端完整回归。本轮未发版。
