# 多版本兼容离线补丁

2026-10-24：当前 hotfix 已扩展为 beta.1～beta.5 统一兼容包；自动发现旧基线和发行流程见 [本次兼容更新记录](BETA5_HOTFIX_COMPATIBLE_UPDATE_20261024.md)。以下为最初 Beta.2 引入格式 2 时的历史记录。

一份补丁兼容多个已发布的来源构建，更新器按本地程序文件的实际大小和 SHA-256 自动选择差分。玩家不再按构建号下载三份不同文件。显示版本、目录名称和本地旧清单都不作为选分支的依据。

本次目标仍是已交付的 Beta.2 构建 `6AC795352BE0`，没有重新打包游戏运行代码。支持三个 Beta.1 来源：`3649400D4B11`、`953CA6DF4CC7`、`639C08B0B49D`。

## 分发与使用

分发以下两项：

- `OrC-KSD-0.0.0-beta.2-compatible-Beta1-to-6AC795352BE0.orcupdate`，2,204,201 字节，约 2.20 MB。
- `OrC-KSD-offline-updater-1.1.0-win-x64.zip`，76,673,393 字节，约 76.67 MB。旧更新器 1.0 不支持新兼容格式，需要这次更换一次。

玩家将新版更新器完整解压到一个独立文件夹，运行其中的“更新游戏.exe”，选择原游戏目录和兼容补丁，关闭游戏后点击更新。保留整个新版更新器文件夹，以后仍用它更新；不要只复制 EXE，也不要把更新器 ZIP 当成补丁。

游戏目录已有不同更新器时，新版从外部运行并保留旧文件；没有更新器时才自动安装。这样可以更新已有旧更新器的安装，不因旧更新器文件不同而阻断，也不会留下混装的更新器。游戏内菜单可能仍启动旧更新器，所以已有旧版的玩家今后应直接使用保留的新文件夹。

卡组、DIY 卡、导入卡图和设置仍保留。原有单来源补丁也能由 1.1 更新器读取。损坏、混装和未收录的构建仍会拒绝更新：兼容多个来源不等于跳过校验。

文件在本地 `dist/`；校验和见 `dist/compatible-SHA256.txt`，验收结果见 `dist/compatible-update-verification.json`。

## 发布工具

更新核心新增格式 2 容器，内部保留每个来源的格式 1 差分，共用按内容哈希命名的数据块。重复新增数据只保存一份。匹配后沿用现有重建、校验、备份、替换、恢复与回退流程；回退恢复被选中的真实来源版本。

CLI 新增 `combine <输出文件> <来源补丁1> <来源补丁2> ...` 和 `inspect-all <文件>`。只能合并相同目标构建、目标版本且来源不重复的补丁。发布工具增加 `-AdditionalBaselineZips`，为额外旧 ZIP 生成差分并合成一个兼容包；发布验收会对每份来源 ZIP 分别运行原生更新器、文件一致性和升级后 EXE 检查。

验证：更新核心 30 项测试通过，覆盖多个来源、过期清单、共享块去重、用户文件、错误来源、损坏块、选择第二来源后的中断与恢复、回退及已有旧更新器。三份真实 Beta.1 均用同一个兼容包通过原生 Godot 更新界面，并验证文件与目标完整包一致、无关文件保留、旧更新器保留、升级后实际 EXE 可运行。发布脚本新增分支通过语法检查；本次直接使用已验收的游戏目标和三个现成差分，不重导出其他正在修改的游戏代码。
