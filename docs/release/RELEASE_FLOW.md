# 当前发布与用户更新流程

更新于 2026-11-15，适用于 beta.12 及后续发行。

## 开发者发布

1. 使用 `tools/version.ps1 -Set <版本>` 同步 VERSION、Godot 显示版本和 Android 递增安装代码。已公开的版本不覆盖重打；修复应使用新版本号。
2. 运行发布相关测试、受影响的 Godot 实际操作验证，以及对应平台的检查。`tools/release.ps1` 默认执行测试和 UI 发布门；只有已经另行完成并保存同等证据时才使用 `-SkipGate`。
3. `tools/release.ps1` 同步短路径工程、导出 Windows 游戏、发布独立服务器和私有 .NET 运行时、构建离线更新器、记录构建清单并生成补丁和完整 ZIP。脚本必须通过解压后的独立 EXE 与工坊验证。
4. 对实际仍在使用的旧构建分别生成补丁。来源必须读取已交付 ZIP 中 `.orcksd-build.json` 的完整 BuildId，不能只按显示版本猜测。beta.12 发布 beta.9、beta.10、beta.11 三个精确来源补丁。旧安装文件若被修改，仍应停止并提示使用完整包。
5. 使用 `tools/export-android.ps1` 导出同版本 APK，检查包名、安装代码、签名连续性、ABI 和 APK 内容；在可用的设备或模拟器上运行回归。覆盖安装不能更换签名。
6. 将完整 ZIP 放在 `dist/releases/<版本>/full/`，APK 放在 `android/`，全部补丁放在 `patches/`；准备对应发行说明。实际运行离线更新器升级旧包，核对升级文件与新完整包一致，并验证玩家文件保留。
7. 提交并推送已验证的源码后运行：

   ```powershell
   python tools/publish-release.py 2.0.0-beta.12 --notes docs/release/RELEASE_2.0.0_BETA12_20261115.md
   ```

   脚本创建草稿发行，上传完整 ZIP、APK、全部补丁、离线更新器、发行说明和 SHA256.txt。逐项核对 GitHub 返回的资产大小与 SHA256 digest，全部通过才公开发行，最后更新固定 `channel` 发行中的 `latest.json`。上传失败不会提前推进客户端清单。
8. 匿名重新获取公开清单与发行资产，核对版本、补丁来源、APK、大小和校验文件；保留发布报告。Release 已存在但资产内容不同应停止检查，不能静默覆盖同版本二进制。

## Windows 用户

- 正常启动发行版后自动检查 `channel/latest.json`；静态清单失败时回退 GitHub API。自动更新关闭或网络失败不影响游戏启动。
- 按当前构建 ID 匹配补丁。beta.12 起页脚显示检查和下载进度；下载完成并通过 SHA256 校验后显示“新版已就绪 · 退出后更新”。
- 正常退出游戏会启动随包提供的更新器。更新器等待游戏进程结束、核对来源文件、应用补丁并保留回滚记录；下次启动使用新版。强制结束进程可能跳过退出钩子，应下次正常启动并退出，或手动运行更新器。
- 没有匹配补丁或缺少更新器时显示发布页入口，用户下载完整包；不在后台擅自下载大体积完整包。完整包应解压到新目录，保留原安装以便核对；用户卡组与工坊位于用户数据目录。
- 点击“检查更新”可手动重试；失败信息与诊断位于用户数据目录 `updates/update.log`。
- beta.9 的旧客户端检查与下载没有可见状态。本版为其提供精确补丁后可恢复原有后台下载路径；新状态界面要升级到 beta.12 后才会出现。

## Android 用户

- beta.12 起启动自动检查，页脚提示存在带 APK 的新版；也可点击检查。
- 点击提示打开 GitHub Release，用户手动下载 APK 并覆盖安装。保留包名、签名与递增 versionCode，应用数据和工坊保持在原应用数据目录。
- 不自动下载、不自动调用安装器、不替换应用文件。系统可能要求用户允许浏览器或文件管理器安装 APK。
- 早期 APK 尚未内置新版提示，需要先手动覆盖安装 beta.12，服务器清单不能给旧 APK 注入界面。

## beta.9 无提示的根因

beta.11 公开清单仅提供 beta.10 的增量补丁。beta.9 因构建 ID 不匹配而选择完整包，旧客户端随后静默跳过完整包；网络正常时也会表现得像没有自动更新。修复同时包含旧构建对应补丁、完整包清单和可见的更新状态，不能仅修改提示文字。
