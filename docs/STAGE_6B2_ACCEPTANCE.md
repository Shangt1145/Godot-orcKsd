# 6B2：指令、条件反制与随机发牌

日期：2026-10-07。版本：`0.0.0-alpha.13`。

## 本轮完成

用户要求指令和反制正常打出、发牌随机。本轮先核对源声明与当前引擎，再装配能够完整执行的代表卡；没有拉取或修改引擎。

- 默认启动真实对局；重开时生成新随机种子。双方独立随机组建 30 张牌组，由引擎洗牌、发起手与换牌；正常流程不固定起手，不强制低费起手。显式种子及固定手牌仅供验证/截图复现。
- 指令从手牌拖到战场使用；直接拖到单位可指定目标，未指定则打开引擎候选窗口。抉择展示真实选项；按钮确认、取消或 Esc 经同一个 responder 回传。非法目标、没有候选、费用不足均不离手、不扣费；退出或取消等待能释放后续操作。
- 指令通过 `BeginCommandPrePlayAsync` 执行。预打出阶段捕获选择，主动 handler 通过引擎运行时与修饰器实现效果；扣费、离手与合法性归引擎。对手驱动也使用该入口。
- 反制从手牌拖到战场激活，预留费用；再次拖出取消并退还原预留额。已接入反制监听真实条件，在任一回合命中后消费一次。激活时不执行条件效果；表现区别激活、取消和条件触发。
- 指令与反制进入既有 FIFO 表现流，保留播放期间的连续输入。窗口验收使用真实鼠标事件。

## 剩余边界

这不是全卡池效果实现。以下三种反制仍明确拒绝，不能以空效果准入：`av76/command/-14`（部署效果打断并消灭）、`deran/command/_5`（亡计触发前抑制）、`USG/commands/_15`（致命攻击随机转移）。当前确认 `card.died` 在亡计结算之后广播，不可用于伪装亡计前打断；现有通用激活信号也不代表条件命中。

未接入的开发、生成、总部附魔、连续手牌选择以及源声明与卡面不一致的指令继续排除。源单位型、国籍、稀有度沿用既有审核映射。总部防御增益按当前引擎单一生命值模型执行。抽牌指令仅抽剩余牌，避开当前引擎空牌库异常；没有新增疲劳规则，回合自动抽空牌库的限制仍存在。秘密费用隐藏、完整热座双方换牌仍待后续。

适配集中在桥接层，UI 只消费 DTO 与 responder。用户通知引擎更新后，先对照 [ENGINE_INTEGRATION_BASELINE.md](ENGINE_INTEGRATION_BASELINE.md) 再拉取、适配和重验。
