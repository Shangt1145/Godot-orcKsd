# 需求 — 引擎整合前的待命准备

引擎远端（`Orc.Ai` + MCP 服务层）与本地谱系（词条程序运行时）已分叉，且对方仍在修 bug。
本需求只覆盖「在对方改完之前，我方要准备到什么程度」，不含合并动作本身。

## 范围
- 包含：整合所需的事实基线、冲突预判、合并顺序与验收清单；对远端变化的监视方式。
- 不包含：任何引擎/游戏本体的代码改动；提交他人未完成的 WIP；发行新版本。

## 约束
- 不得改动工作区里属于他人的未提交修改。
- 结论必须来自代码取证，不得凭印象断言「哪里冲突」。

## 需求条目

### R1: 整合预案
- 状态：确认
- 场景/触发：对方宣布改完、要求开始整合时
- 行为：能在当天拿出一份合并方案——涵盖两条谱系的提交取舍、已知冲突文件、API 破坏点、验收步骤。
- 验收：
  - [x] 列出本地 3 个提交与远端 6 个提交的取舍结论 → 全保留（1122 绿实测）
  - [x] 列出已知会冲突的文件与原因 → 实际交集为 0；真阻塞是 `Orc.Mcp/Tools` 未入库
  - [x] 给出对手驱动归属的两种形态各自的改动面 → 预案 D1
  - [x] 给出整合后的验收命令与通过判据 → 预案第五、七节
- 产出：`整合预案.md`

### R2: 基线可回退
- 状态：草拟（用户裁定本轮不做）
- 场景/触发：整合失败时
- 行为：整合前存在一份可回退的锚点（提交 + 可运行包）。
- 验收：
  - [x] 当前引擎/游戏本体的确切版本可复述 → 引擎 `12d1aeb`，整合分支 `785244f`
  - [ ] 存在一份可直接发给玩家的完整包（当前 `dist` 只有 11:43 的旧包）

### R3: 远端变化监视
- 状态：确认
- 场景/触发：对方每次推送后
- 行为：能回答「远端又动了什么、是否已经收敛」。
- 验收：
  - [x] 一条命令即可列出远端新增提交与受影响源码面 → `tools\engine-drift.ps1`（`-Fetch` 才联网）
