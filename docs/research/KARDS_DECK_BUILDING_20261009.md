# 卡组构筑：原版调研与本项目实现（A.16）

调研日期：2026-10-09。规则依据为 KARDS 官方说明及开发者公告，未将玩家讨论当作规则来源。

## 原版机制

| 项目 | 原版规则 | 本项目 |
|---|---|---|
| 张数 | 总计 40，包含 1 张总部及 39 张卡牌 | 新建卡组默认 40；输入框明确标注含总部 |
| 国家 | 一主国、一盟国，最多两个国家；主国至少 28（总部 + 27） | 使用当前卡池的国家标识；总部另计，不加入抽牌名单 |
| 盟国 | 最多 12 张；不允许盟国精英卡 | 校验且限制新增；可以选盟国而不加入盟国卡牌 |
| 同名卡 | 普通 4、限定 3、特殊 2、精英 1 | 增减按钮、验证及实际开局共用同一套上限 |
| 标准与经典 | 含 Reserve 卡的卡组用于 Classic，不能参加标准排位 | 本项目没有 Reserve 或账号库存数据，不虚构赛季合法性 |
| 构筑辅助 | 搜索、国家/费用/类型/稀有度筛选，费用分布，保存和导入导出 | 接入本地构筑与管理；代码为本项目 ORK1 格式 |

## 用户要求的选项

**不限制主盟国**取消两国限制、盟国 12 张限制及盟国精英限制，允许不同国家混编。稀有度同名卡上限、衍生卡禁用和实战支持审核继续生效。主国字段仍用于总部及引擎构筑元数据。

**总张数（含总部）**可自定义为 6–512；实际抽牌名单始终是总张数减一。另有 **不限张数**，可直接按当前所选张数开局，不强制凑到固定目标。引擎默认后手起手为 5，故实战卡组至少有 5 张卡牌；持久化容量保护为 511 张卡牌。自定义固定张数不按比例放大盟国上限，未取消国家限制时仍最多 12 张盟国卡。

“标准规则”恢复 40 张、国家限制及固定张数。切换选项保留已选卡牌；不符规则的旧卡显示问题，可移除修正，不暗中删卡或替换。

## 卡池、稀有度与原生引擎

原始参考项目 `game/js/card-import.js` 第 41 行明确声明 `Standard → iron`、`Limited → bronze`、`Special → silver`、`Elite → gold`。`orc.js` 的稀有度条件解析使用相同对应。因此修正了桥接层此前把金属稀有度统一编译为 Standard 的处理；未修改源卡牌声明或审核哈希。

当前只有 21 种卡牌完整通过语义审核（9 单位、11 指令、1 反制）。对应稀有度容量为 av76 25、deran 26、USG 16、UN 0。没有任何主国能凑到标准要求的 27 张主国卡，所以首次启动的可玩初始卡组明确使用 **混编初始卡组**，39 张卡牌 + 总部，并显式开启不限国家。新建卡组仍默认采用标准构筑规则。

取消“仅实战可用”可用完整卡池构筑草稿。未支持、已变更、失踪或衍生卡不会绕过开局审核；不能用随机牌组偷偷替代用户保存的卡组。

当前可映射的主国为 av76 / deran / USG / UN；这是本项目卡池标识，对应引擎 Soviet / Germany / USA / Britain，并非把这些原创国家改名为原版国家。未映射国家可混编进草稿，但暂不能实战。引擎的构筑元数据需要完整主盟国对；界面保留盟国选择，允许其卡牌数量为零。有效配置在初始化时传入原生 `PlayerDeckConfiguration`。

玩家使用所选已保存卡组的精确名单，由引擎洗牌及发牌。自动对手从审核集按稀有度上限随机组同等张数卡组。显式验证场景仍使用原有固定测试牌组，生产入口不使用测试起手牌覆盖。

## 保存与操作

- “卡组构筑”：名称、主盟国、规则选项、搜索及筛选、点卡加入、列表增减、长按详情、卡类/国家统计与费用曲线。
- “我的卡组”：新建、编辑、复制、删除确认、设为对战卡组、直接对战、代码导入导出。战斗齿轮菜单有构筑和管理入口。
- 草稿可保存，实战必须通过完整校验。编辑、复制、导入不改变当前对战卡组；“使用并对战”先保存并启用，再启动。
- 数据存于 Godot `user://decks.json`，带版本号，通过临时文件替换保存；写入失败回滚内存。损坏或未来版本的文件保留，明确显示读取失败，避免覆盖。
- 卡组代码为 `ORK1:`，携带名称、名单、国家与张数设置，导入创建新 ID。与原版 KARDS 代码不兼容。
- 未保存的编辑跨导航保留；打开其他卡组或新建前提示丢弃修改。清空只影响当前编辑稿，保存后才覆盖。

## 验收

构筑测试覆盖稀有度上限、40 含总部、自定义及不定张数、主盟国/精英/12 张盟国限制、未支持卡拒绝、存储快照、复制身份、重启加载、损坏文件保护及写入回滚。原生对局验证实际名单及 39 / 30 / 16 张卡牌，主盟国元数据与正常发牌；禁止起手覆盖和随机回退。

`--verify-decks` 使用真实鼠标输入验证加入、移除、保存草稿、复制、删除确认、导出、无效导入留在弹窗、有效导入、两个张数的真实开局与换牌。`--capture-decks` 额外保存构筑与管理页截图。验证使用 `res://artifacts/decks/session-<id>.json`，不读取或修改玩家卡组文件。完整 `--verify-ui` 包含卡组场景及原有回合、动画、目标选择和对战检查。

本阶段完成本地构筑系统，不扩充 21 种卡的效果支持集，也不宣称疲劳、官方账号库存或排位机制已经接入。

最终验证结果：编译 0 警告 / 0 错误；208 项测试全部通过；完整界面输出 `UI_VERIFY_OK`；1280×720 和 1600×900 的构筑操作均输出 `DECK_VERIFY_OK`，截图已检查且保存在 `artifacts/decks/`。引擎仍为 `8b0ae98`，原有 `PlayManager.cs` 修改哈希保持不变。
