## 核心观察

原版的质感来自清楚的动作因果、纸卡重量和武器差异。普通操作应短促、连贯；重击、毁灭和胜负才拉开强度。不能用统一加长停顿、全屏闪白或提高震屏幅度代替。

## 建议实施顺序

### 用户补充：卡牌动作缺失与僵硬

用户明确指出卡牌本身也缺少很多动作。下一轮优先级据此调整：**先补卡牌交互与姿态衔接，再补武器特效**。不能把本轮问题归结为爆炸素材不足。

源码复核发现：`BattleScreen.CardHovered` 对手牌悬停直接写入 `Position = RestPosition + (0,-90)`、`Rotation = 0`，退出时直接复原；部分取消路径同样直接恢复位置和旋转。这些路径存在明确的姿态跳变，不是缺少更多粒子。

| 卡牌动作 | 本轮判定与改进方向 |
| --- | --- |
| 悬停浏览 | 已有抬牌，但采用直接赋值。进入、移出与快速横扫手牌需要连续过渡，保持命中区域稳定，避免反复触发鼠标进入／离开 |
| 拖起与跟手 | 核对按下点、拖拽阈值与抓取锚点；位置保持跟手，角度和阴影可稍滞后。不能为了柔和而让整张牌追不上鼠标 |
| 松手与取消回手 | 无效落点、右键、Esc、引擎拒绝应从当前姿态返回实际手牌位置；不要瞬移或先回原位再开始另一动画 |
| 抽牌入手 | 当前已有曲线飞行、翻面与展示，并非完全缺失。应核对展示→入扇形→邻牌让位是否连续，而不是重复增加翻牌 |
| 手牌重排 | 已有部分位置插值；需要覆盖增减牌、快速悬停、抽牌中拿走、拖出与放回。位置、旋转、尺寸和层级应由同一姿态过渡接管 |
| 出牌形态切换 | 完整手牌→场上紧凑卡需要保持视觉中心与可见实例连续；跨快照重建时不能闪回、重复出现或突然换尺寸 |
| 翻面与纸感 | 抽牌已有宽度压缩和轻微剪切。继续核对透视、阴影和正反面切换的接续，不能把所有翻面都当成单纯横向缩放 |
| 战场卡移动与让位 | 检查起步、抬起、落定及邻卡重排；允许动作存在先后层次，避免所有对象同时起步、同时停下 |
| 退回手牌／变形／控制权变化／生成与移除 | 分别建立真实事件样本核对覆盖率。本轮尚未逐条确认缺失，不能因没有独立方法名便宣称未实现，也不能默认普通位移已覆盖全部 |

验收应包含慢速录屏和快速连续操作。平滑过渡须可打断：新目标从当前显示姿态继续，不能先归零；重绘、断线和切换视角不能留下旧 Tween 与新状态争抢同一张牌。

下面原有攻击实施顺序保留作为第二阶段。

1. **先做对照录像**：当前版本固定场景覆盖步兵连射、坦克单发、炮兵、飞机、连续攻击、致死与 HQ；记录声音和完整前后状态。使用视觉夹具隔离引擎移动阻塞，但另保留真实事件链验证，不以夹具代替实战验收。
2. **优先补命中与残留**：枪口、弹道、闪光、盾牌数字、烟尘分别定位；残留效果拥有独立生命周期。普通攻击结束后可继续，烟尘不截断。
3. **细分武器音画**：表现配置使用默认分类加覆盖字段，不通过卡名或效果文案猜规则；射速和声音同步，未配置的 DIY 卡有稳定默认值。
4. **再完善移动、死亡和重击层次**：保持纸卡，不做实体坦克撞击替代所有攻击；减少普通动作抢眼的全桌震动，让 HQ 与大规模效果有强度空间。
5. **最后校准抽牌、回合及特殊效果**：补齐连续录像证据后再定时长；沿用已确认的部署、抉择参考。

## 验收要求

- 同一动作提供原片／项目片段、对应时码和阶段图，明确哪些为观察、哪些为近似设计。
- 覆盖正常、快速、极快、减弱动效；音画同步不能依靠固定额外 sleep。
- 覆盖连续攻击、双方死亡、反击、触发链、对手出牌、观战与回放；UI 不重新计算伤害、胜负或合法目标。
- 余效有数量上限和回收机制，重开／离开仍全部清理；普通新动作不整批清掉还应可见的残烟。
- 真实事件播放与录制预览共用演出实现。当前引擎已有战斗阻塞须单独列出，不宣称已解决。
