# 对局反馈修复（2026-10-24）

承接玩家用混编卡组实玩后指出的四个问题。本轮修改位于 UI、桥接投影与演出调度，不需要改写玩家卡组或工坊存档，也未推送或重新发布 ZIP。

## 修改

- 回合抽牌先闪入手牌、再消失重播：嵌套引擎片段的完整快照可能早于 `drawn/hand.add` 通知包含新牌。现在首次可见的新牌就安排抽牌演出，调度在此前的回合横幅阶段排除它；之后收到同一张牌的通知不再重复播放。
- 数字偏上：场上攻防、总部防御、费用和操作费用下移 3 个设计像素；生成卡面的数值文字下移 10 个卡面设计像素（普通手牌约 3 像素）；指挥点主数字下移 4、槽数及牌堆数量下移 3；伤害预览与伤害跳字同步下调。原始卡图中已烘焙的数字没有重绘。
- 缠斗部署反复回手、选靶无反应：待选靶期间保留已确认落点的场上预览，快照刷新和请求切换不再把它恢复成手牌，也不创建回手残影。既可从单位拖箭头，也可点击有效目标，均在松手时确认。部署操作留下的旧松手不会穿透回答新请求；右键取消仍回手且不扣费。
- 多单位更新与消灭拖沓：同一次结果里连续的不同单位状态变化、消灭分别合批同时播放，同一单位的连续变化保留顺序。状态提示由 0.80 秒缩到 0.34 秒，普通单位消灭等待由 0.68 秒缩到 0.40 秒；同步缩短烟尘、碎片和伤害跳字，避免后续动作继续等残留特效。总部终结演出保留原时长。

## 验证和边界

- `PresentationArrivalTests` 新增 3 项：首次快照安排抽牌及迟到通知去重、回合横幅不提前暴露新牌、不同单位合批且同一单位保序。
- UI 全量：549/552 通过，失败仍为此前已有的三个 `OfficialCardExpansionTests`（献祭取消及混合单位/总部伤害两例），无新增失败。报告 `tests/TestResults/battle-feedback-full-20261024.trx`。
- Godot `--verify-battle-feedback` 在无头与 Vulkan 窗口两种模式均退出 0。检查抽牌开始前每帧没有新牌、从牌堆开始且只播放一次；部署预览跨三次刷新和关闭/重开请求不回手且无残影；目标点击松手提交一次；三个单位的状态和消灭分别在 40 毫秒内同时开始。
- 同一入口继续运行原有箭头、原生部署取消/重试、真实保存示范包检查：缠斗落点后选靶及原生关联通过，装填/生成发射及独立发射通过，`findings=0`，工坊文件保持不变。
- 完整单机链 `--verify-ui` 退出 0：`UI_VERIFY_OK screens=11 cards=521 texture_cache=64/64`，包含原有战斗、选靶、部署、终局和卡组检查。日志 `artifacts/battle-feedback-ui-chain-20261024.log`。
- 日志：`artifacts/battle-feedback-20261024-headless.log`、`artifacts/battle-feedback-20261024-vulkan.log`。画面：运行副本 `H:/g/kards/artifacts/battle-feedback-20261024/`。

这些定向回归不是完整混编长局验收。此前正常玩家流程仅玩到第六个己方回合，未完成一局；本轮未据此宣称整包或联机已通过。引擎修复及明天更新注意事项继续见 [机制示范包兼容修复](DEMO_MECHANICS_COMPAT_20261023.md)。
