# 工坊卡包与扩展包联机（2026-10-25）

已接通当前开发源码的工坊卡包联机流程。客户端和随包服务端必须一起更新；此前 beta.7 发行文件不会自动获得此功能。

## 玩家流程

1. 在工坊保存 DIY 卡牌，或导入并启用原生卡包；扩展包与其基础包一起准备。
2. 用当前可执行卡牌组成合法的 39 张卡组，选择好友对战并创建或加入房间。
3. 房主批准玩家入场。双方自动比较包的真实内容摘要并同步缺少的包与卡图。
4. 如果好友携带房主没有的卡包，房主需开启房间中的「接收好友卡包」。界面明确说明会载入好友提供的效果脚本；默认关闭。
5. 房间显示「双方卡池已对齐」后，由房主开局。同名但内容不同的包会点名提示，并阻止开局，需统一版本后重新开房。

工坊原有 `diy/` 标识仍用于编辑器与玩家卡组存档。进入房间时编译到临时原生包，并映射为稳定的 `pack/包/card.…` 标识；不改写原存档。基础包、扩展包的卡牌引用和自定义词条一并处理。原生工坊包取自当前启用目录，不再只扫描随游戏附带的目录。未完成的草稿不作为可玩卡同步；选中的卡编译失败会报错。

收到的资源仅保存在联机会话目录，不注册到本机单机、构筑或工坊。下载只用于显示；规则与效果脚本在房主服务端执行。关闭并重开房间时重新冻结本机内容，编辑中的草稿不会暗中改变正在进行的对局。

## 实现与协议

- `NetworkWorkshopSession` 冻结启用的原生目录，并将兼容工坊卡编译为含正确 sidecar GUID、正式 lock、内联效果、卡面文本、词条及卡图的原生包。关联卡引用随会话 ID 一起映射。
- `pack-transfer-v1` 提供 `pool.manifest / pool.fetch / pool.offer / pool.chunk / pool.commit / pool.ack`，沿已建立的 JSON-RPC 连接传输，不需要额外端口。
- 分块 256 KiB；块、压缩包和解压目录均校验 SHA-256。单包最多 256 MiB、8192 文件；房间压缩包缓存最多 512 MiB。拒绝目录穿越、设备名、链接及大小写重复路径。
- 未批准连接不能读取或上传卡包；观战者可取回展示资料，不能上传或确认玩家卡池。允许接收的开关只通过房主管理通道设置。
- `pool.ack` 与座位令牌、房间和真实卡池指纹绑定；新增包后原指纹失效。开局在服务端检查双方确认，不能只绕过按钮启动。
- 收到的包注册到服务端会话暂存目录，使用原生卡池装配与规则校验。房间轮换时移除收到的包并关闭接收开关。
- 客户端断线后从新连接重新核对卡包；保留的会话缓存可复用。未完成下载不会进入正式缓存。客户端本地冻结目录在超过 24 小时后于下一次准备会话时清理。

## 验证边界

新增回归使用真实服务端子进程与两个 TCP 客户端，覆盖基础包/扩展包的不同持有情况、接收开关、规则冲突、正式 39 张构筑、自定义程序/声明式词条、跨卡引用、超过单块的卡图、换牌、出牌结算、重连与认输终局。服务端另测未批准访问、管理权限和不安全路径。

- 联机工坊专项：7/7。另验证同一卡包不受无关已安装国家/词条及其他所选包影响。
- 服务端完整回归：127/127。
- 客户端先前完整回归：602/602；增加隔离回归后的完整运行：602/603，唯一失败为原有 DesktopAuthoring 全语料测试触发 15 秒脚本超时。该项随后单独复跑通过（约 4 秒），没有修改解析器或放宽超时。
- Godot `--verify-room`：`ROOM_VERIFY_OK`，覆盖建房、占座、AI、开局、卡图、换牌、出牌及回合交还。验证日志保存在 `artifacts/network-workshop-room-direct.log`。
- 引擎配套补丁已在当前工作副本通过 `git apply --reverse --check`。

这证明本机多客户端闭环；不等同于两台不同机器的公网长局验收，也不保证任意新增规则脚本或所有机制组合都已验证。原始源卡与不可执行草稿继续不在联机准入范围内。词条主动技能沿用此前联机尚无操作入口的边界，本次不新增其操作界面。
