# 6D2：行动判定、阵型空隙部署与抽牌接管

日期：2026-10-11。版本：`0.0.0-alpha.20`（A.20）。

用户要求修改当前引擎的行动入口，UI 维护交互状态机；部署候选应为支援阵型中所有单位及总部之间、两端的空隙。后续明确：未操作的牌不能因动画被锁住，新抽牌飞行到一半也要能拖动并打出。

## 行动入口和状态边界

- 引擎注册内置 `action.input.allowed` 判定器，通过 `Match.InteractionStateReader` 在每次查询与提交时读取值状态；没有前端读者时保持无界面引擎行为。
- UI 状态包含可操作/拖拽、选择、回合切换、暂停，以及已提交操作源的 UID。引擎仍决定回合、归属、费用、单位行动资格和合法候选；前端状态只能收窄入口，不能赋予规则上非法的行动。
- 打牌、单位指挥、结束回合走入口复验；原生效果生成单位的 `JoinUnitAsync` 不读取手势状态。旧的直接槽位部署接口保留给底层兼容调用，也读取前端占用限制。
- `PlayManager.CanPlay` 是原生入口可用性查询，执行验证判定器而不执行卡牌效果。UI 将 `HandPlayabilityKnown` 设为 true；效果内部选择和最终提交仍会复验，因此入口可用不承诺每种效果目标都合法。
- 已操作的源对象在自己的演出完成前保留占用，拒绝/取消则释放。抽牌、伤害目标、参值变化和阵型重排不占用未操作的对象；其他合法行动可以继续提交。未操作的牌也不会因为指向一个正在演出的对象而被输入判定器锁住，目标是否合法仍由原生规则决定。
- 新局和换牌结束时，先应用 UI 阶段，再重新读取原生行动，立即恢复当前阶段的可操作状态。
- 已接纳行动的后续选择属于该行动的延续，桥接只允许它完成，不开放新的并发行动。结束回合先经过原生接纳，再立即锁定战场；自动对手后台提前回到友方逻辑回合时仍保持锁定，直到演出进入友方回合。结束回合按钮保留友方橙色、敌方灰色。

## 支援部署

`BattleLine.GetInsertionGaps()` 返回阵型的顺序边界：N 个已占用实体（含总部）对应 N+1 个可插入空隙；容量满时为零。总部不再固定留在索引 2，规则读取它实际的 `Hq.Position`。

每个 `FormationGap` 有独立 ID、顺序、左右锚点和当前占用快照。重复读取未变化的阵型会复用 ID；阵型变化后旧候选失效。UI 拖牌时取得候选、显示边界位置，松手提交 `GapId`，不把插入序号映射成任意空存储槽。命名落点失效时明确返回 `FormationGapUnavailable`，不会改用第一处空位。

原生打出验证通过后，引擎按所选边界插入，保留既有实体的相对顺序，并一起更新单位与总部的实际槽位。费用复验失败或旧候选拒绝时不重排、不离手、不扣费。槽位继续作为底层存储，前线移动模型保持现有实现。

## 飞行中抽牌

友方抽牌从飞行开始就使用真实 `BattleCard` 交互对象，点击位置跟随实际变换，不要求牌先到最终手牌位置。鼠标按下后仅停止这张牌的抽牌补间，恢复正面，由正常拖拽接管；合法打出立即提交给引擎。

调度仍遵循抽到该牌、使用该牌的因果顺序。接管结束该张飞行动画，不中断整条表现队列；后续抽牌继续依次播放。松手位置作为后续打出演出的起点保留，旧抽牌投影不会把已打出的牌重新画回手牌。敌方回合输入锁继续覆盖该对象。
