# 6C2 通用多选与候选卡面验收

日期：2026-10-09。版本：`0.0.0-alpha.15`（A.15）。引擎继续使用 `8b0ae98158394cae264b4ed80dfa10fb506e7351`，本阶段没有重新拉取或改动上游。

## 完成范围

- 通用多选复用调度面板的 `MulliganStamp` 红圈叉号。点击标记，再次点击取消标记，每页五张，选择跨页保留。
- 下方只保留翻页按钮及“已选数量/需要选择数量”，例如 `1/2`；没有数量说明、确认按钮或页码。需选数量来自原生请求的 Max。
- 按用户要求，必须选满 Max 后自动提交一次。少选、不选都不能提交；Enter、数字键盘 Enter、Space、Esc 等键盘输入不能提交或取消。单选点击即提交。鼠标右键或空白仍可取消并释放请求。
- 原生 Min/Max 和候选保留在 DTO 中；界面采用上述明确的满额选择方式。原生引擎仍独立验证数量、成员与目标状态。桥接契约中的零选择测试不等于界面提供零选入口。
- 原生 `Hand` 多引用映射完整 UID 列表；连续 `CardPickerList` 的注册定义直接映射真实名称、卡面和费用。仅读取定义，不实例化、不加入手牌、不代替效果生成卡。
- 隐藏引用没有卡面时只显示背面，不用原指令冒充目标。未知定义显示占位说明，不凭标识生成游戏卡。
- 取消和拒绝保留现有请求隔离：取消回手，拒绝保留标记供重新选择；连续请求不会被上一请求关闭；多选结束后使用原指令卡面进入最后展示段，停靠中心保持一致。
- 单人换牌增加请求标识、未知 UID 与重复 UID 校验，过期回答不能完成当前请求。现有手牌/牌库数量守恒保持。
- 按用户要求删除本地同屏双人入口、切换界面和双方真人换牌流程。产品只保留玩家对本地对手。内部 `ManualOpponentForVerification` 与观察视角切换只用于固定场景验收，没有菜单入口。

## 验证

- 客户端 186 项测试通过，新增单人换牌过期/未知/重复回答、挂起请求退出，以及真实指令中的多引用、连续定义候选、空契约回答和取消场景。
- `--verify-stage6c2`：三档速度 × 普通/减少动态 × 两种原生 Min，共 12 组真实鼠标路径。检查调度红圈叉号、点击取消标记、跨页计数、满额自动提交、拒绝后重选、来源卡面和停靠位置。
- 同时注入 Enter、数字键盘 Enter、Space、Esc，并直接尝试少选/零选，均不提交或取消。无候选请求可以通过鼠标右键结束。
- 1280×720 与 1600×900 的真实图形窗口验收并看图检查；下方只有翻页和已选/需选计数。截图及日志保存在 `artifacts/stage6c2`。
- 完整界面回归通过：7 个界面、315 张图鉴、576 张资源、20 个部署手势场景、36 组部署演出、真实换牌/引擎/指令、敌方回合输入锁、连续操作和表现优先队列。最终选择规则调整另以专项重复验证。
- `--verify-orders` 复验原有单选、连续请求、指令与反制回手。
- 运行副本 `H:/g/kards` 同步为 A.15，并清理本次曾复制的双人交接文件。
