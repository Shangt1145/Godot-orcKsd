# Beta.1 离线增量更新

整个游戏和更新界面均为原生 Godot；更新核心是独立 .NET 库，游戏规则仍由 OrC-KSD 执行。不连接更新服务器，不需要玩家安装 SDK。

## 玩家使用

1. 首次升级，解压 `OrC-KSD-offline-updater-1.0.0-win-x64.zip`，保留 EXE、PCK 和运行库文件夹。
2. 打开“更新游戏.exe”，选择旧游戏中 `KardsUi.exe` 所在的文件夹。
3. 选择对应的 `.orcupdate` 补丁，点击“更新”。游戏正在运行时会等待，关闭游戏后继续；等待或准备期间可以取消。
4. 完成后点击“启动游戏”。更新器会安装到游戏文件夹，以后从游戏顶部“离线更新”进入，只下载补丁即可。

同为 Beta.1 的构建也可能不同：按补丁显示的来源构建编号匹配。补丁不匹配或旧文件被修改时会停止，明确显示所需构建与出错文件，不修改其他程序文件。完整包仍作为新安装方式发布。

成功更新后保留最近一次回退，可在更新器中点击“回退上一版”。中断后重新打开更新器会恢复；新版游戏发现未完成事务时先打开更新器，避免在混合版本文件上开局。

## 差分与文件约束

- `.orcupdate` 是格式版本 1 的 ZIP：`patch.json` 记录完整来源/目标清单及变更片段，`blocks/*.br` 存放 Brotli 压缩的新增内容。
- 每个文件记录相对路径、大小、SHA-256。构建编号由有序文件清单生成，与显示版本分离；不依赖安装目录名或仅比较版本文字。
- 内容定义分块：最小 16 KiB、边界掩码 65535、最大 256 KiB。按块哈希复用旧文件的偏移与长度；数据插入后仍可重新对齐。PCK 在本地完整重建，不逐次叠加资源覆盖包。
- 清单管理 `KardsUi.exe`、`KardsUi.pck` 和 `data_Kards.Ui_windows_x86_64/`。更新器使用独立 EXE/PCK/运行库，不替换自身正在执行的文件。
- 只操作来源和目标清单中的游戏文件；目标新增文件与玩家已有文件重名时拒绝覆盖。路径穿越、重复清单、越界片段、损坏或缺失数据均拒绝；不沿目录联接写入。
- 卡组、DIY、导入记录、卡图和设置仍在原来的 `user://` 下。项目名称和用户数据路径保持不变；本轮不做存档结构迁移。原生卡包缓存仍由内容哈希隔离。

## 安装事务

安装目录内 `.orcksd-build.json` 记录当前构建，`.orcksd-update/` 是更新器工作区。独占锁阻止两个更新器同时操作同一安装。

先校验来源和空间，再在 `pending/stage` 重建所有变化文件并检查目标哈希。提交前再次等待游戏退出并复验来源；提交期间关闭取消入口。旧文件移动到备份后替换，更新日志以原子写入和落盘刷新保存阶段。异常立即恢复；真实进程中断后，下次启动按日志恢复或完成提交。

成功后 `pending` 成为 `rollback`；下一次成功升级才替换此前的回退备份。恢复过程可重复执行，意外的额外文件修改会明确报错并保留恢复材料。

## 开发与发布

```powershell
# 默认保留上次交付的 ZIP 作为来源；也可明确指定旧包和旧显示版本。
./tools/release.ps1 -BaselineZip "旧版完整包.zip" -BaselineVersion "0.0.0-beta.1"

# 单独生成差分：旧 ZIP 或目录、新版游戏导出目录、输出补丁、双方显示版本。
dotnet run --project tools/OfflineUpdate/OrC.Update.Cli -- build "旧版.zip" "新版目录" "升级.orcupdate" "0.0.0-beta.1" "0.0.0-beta.1"

# 更新核心专项测试。
dotnet test tests/Kards.Ui.Tests.csproj --filter FullyQualifiedName~OfflineUpdateTests
```

发布脚本同时生成完整包、首次更新器 ZIP、对应增量补丁、校验和及 `offline-update-report.json`。报告单独记录完整包、更新器、补丁和首次下载体积，以及补丁减少比例。旧 ZIP 先存入 `artifacts/update-baselines/`，同显示版本发布不会丢失生成补丁的基线。未来带构建清单的旧 ZIP 自动提供来源显示版本；没有清单且改过文件名的历史包应明确传入 `-BaselineVersion`。

发布门包含更新测试；即使使用 `-SkipGate`，仍强制执行：完整包独立 EXE 验证、旧 ZIP 实际解压、真实 Godot 更新界面的补丁选择/更新按钮流程、结果文件与完整包比较，以及更新后玩家 EXE 的卡图、卡牌、构筑和开局验证。运行库完整随包交付。
