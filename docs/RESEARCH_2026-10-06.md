## 二、P9 崩溃：真因已确认（在 UI 侧，可修）

旧结论「疑似引擎 a24ef2d 效果系统装配导致栈溢出」—— **不成立**。
`tools/deploy_crash_probe.py` 与 `tools/attack_feasibility_probe.py`逐步二分后结论：

### 逐步排除

| 变量 | 结果 |
|---|---|
| `seed: 11` vs `7` | 无关 |
| 订阅 `host.CombatReady` | 无关 |
| 完整链路（部署→移动→攻击→敌方 AI） | 无关（57ms 通过） |
| interactables 传空列表 | 无关 |
| interactables 传真实槽位+HQ | **无关**（15s 正常完成） |

### 实际原因：UI 侧时序缺陷

第一次探针挂在 `BeginUnitPrePlayAsync`，看似引擎问题。真因是**探针自身写错了**：

```csharp
var match = NewMatch(...);            // 构造
holder.Add(match.Players[1].Hq.Ref);   // ← 在 Initialize 之前访问 Players
```

引擎抛 `InvalidOperationException: 对局尚未进入'进行'态：管理器群不可用`，
`Match.RequireReady` 拦截。修正为**先 `await InitializeAsync()` 再填引用**后，
全真实引用路径 15 秒内正常跑完，不挂死。

**结论：P9 阻塞点解除。** 引擎侧目标解析没有问题，
`unit.damage.dealt` 可以正常消费。P9 可立即开工。

> 教训：这一次的"引擎有 bug"是我自己的探针写错造成的。
> 旧面包屑只说明进程死在某个调用之后，不足以归因到引擎——
> 应先怀疑自己的最小复现是否忠实于真实调用序列。
