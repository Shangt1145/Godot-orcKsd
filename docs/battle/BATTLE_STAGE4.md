# 对战 UI 第四阶段：连贯抽牌、反制与状态变化

日期：2026-10-05。本阶段继续只做 UI，由示例或外部已解决结果驱动，没有修改主引擎架构或实现正式规则。

## 抽牌修正

我方抽牌现在在一段 0.78 秒轨迹内同时移动、翻面、放大和倾斜：卡背从右下牌堆出发，沿轻微弧线进入棋盘中央；在途中侧缘最窄时切换正面，带斜切、透视压缩与惯性转角。中央位置按卡面中心 `(640, 360)` 对齐，放大到 1.42 倍，停留 0.55 秒，再缓动进入手牌。

翻面不再等待移动结束，揭示不再停靠右侧。同一方连续抽牌使用相同轨迹，但每张缩短为 0.52 秒移动翻面、0.20 秒中央停留和 0.30 秒入手；单张抽牌仍为 0.78 / 0.55 / 0.42 秒。仅相邻的同方抽牌步骤启用加速，被其他动作隔开的抽牌保持单张节奏。对手抽牌仍只露卡背；减弱动效跳过翻转与大幅位移。

这是 Godot 原生纸卡演出，使用现有正面纹理与卡背。斜切与宽度变化属于 UI 的透视近似，时长和曲线是可调表现参数。

## 第四阶段范围

- **反制武装/解除**：卡保留在我方手牌，黄色费用底代表已武装；解除恢复原费用底。展示值直接来自快照的 `IsCounterArmed`，UI 不计算扣费、退款或触发条件。
- **反制触发**：按适配器给出的步骤展示触发动作、揭示反制与结算效果。远程打击示例为敌方单位先部署到支援线，反制再弹出，随后消灭刚部署的单位；反制卡在销毁效果期间保持可见。直接消灭不伪造伤害数字，也不把部署显示成“已阻止”。只有外部明确提供 `BlockedCard` 的其他取消型效果才使用该反馈。只按最终投影消费结果，不自行决定触发、阻止、重定向或死亡。
- **隐藏信息**：对手武装/解除的卡牌身份在冻结时丢弃，不生成历史卡面或战场卡；公开资源继续使用适配器提供的可见值。只有明确揭示的反制进入历史。
- **治疗与强化**：绿色数值反馈、轻微纸卡脉冲；不使用伤害爆炸。直接展示新的有效攻防和生命值。
- **压制与解除**：临时文字反馈与已有卡面压制遮罩，解除后按新快照恢复。
- **费用变化**：短时费用反馈；手牌上的有效费用覆盖烘焙卡面中的旧费用。

齿轮菜单新增七个场景：反制武装、取消武装、反制触发、治疗、强化、压制与解除、费用变化。外部状态模式禁用本地演示入口。

反制武装在手牌内、黄色费用底和触发后公开的语义依据为 [官方反制说明](https://support.kards.com/hc/en-us/articles/360026404872-Countermeasure)。完整反制演出与状态专用素材仍缺少无剪辑原版录像对照；本阶段没有声称逐帧等同原版。

## 接口与验证

沿用 `Main.PresentSequenceAsync`；载荷增加 `UiCounterPresentation` 和 `UiStatusPresentation`，并用 `UiDeploymentPresentation` 的中间投影与 `UiRemovalPresentation` 明确区分部署和消灭。全部传入角色和嵌套集合都在演出前冻结。状态步骤要求前后 UID 一致且目标当前公开；隐藏目标不播放可见反馈。

取消、切页和设置变化直接消费已提交的 `After`；新投影和复位使旧任务失效。临时卡、斜切、缩放、烟火和输入锁必须清理。这些仍是 UI 候选接口，不要求主引擎采用对应内部结构。

```powershell
& 'H:\Working Folder\OrC-KSD.Godot\tools\run.ps1' -Test -Verify
& 'H:\Working Folder\OrC-KSD.Godot\tools\run.ps1' -Capture
```

既有消费层测试及前三阶段场景检查保留。第四阶段检查包括：移动中翻面与中央对齐、武装不离手、解除和触发退场、远程打击的落位/揭示/销毁顺序及无伪造伤害、对手隐私、治疗/强化/压制解除/有效费用、各阶段中断以及减弱动效。

日志：`artifacts/battle-stage4-verify.log`、`artifacts/battle-stage4-capture.log`、`artifacts/battle-stage4-scene-final.log`。第四阶段截图为 `artifacts/battle-stage4-*.png`；修正后的抽牌途中和中央停留画面仍在 `artifacts/battle-stage3-draw*.png`。

本地示例使用现有卡牌身份和明确的示例前后状态；不是完整卡牌效果实现。后续继续处理起手换牌、弃牌/爆牌、选择、回合反馈及各类专用武器/状态素材。

## 支援线落位修正

总部可位于单位队列内部，单位能部署在其左右两侧。点击/拖放位置决定 `PlayCard.SupportIndex`（包括总部在内的插入位置），本地演示保持总部与单位的相对顺序。移动和退场后重新编号，避免剩余单位换到总部另一侧。外部模式只发送位置意图，等待提供方投影实际落位。GUI 场景检查覆盖左、右两侧拖放，日志为 `artifacts/hq-both-sides-verify.log`。
