# 6D1：DIY 卡牌创作与真实试打

日期：2026-10-11。版本 A.19。继续使用现有引擎，不更新或修改引擎源码。

## 交付计划

1. 值对象草稿与本地卡库：新建、修改、复制、确认删除、原子保存、重新载入和卡牌代码导入导出。
2. 用现有引擎的卡牌定义、DSL 编译器、效果模板、脚本编译与预制体装载链完成校验；生成原生单卡 JSON。
3. 用真正的编辑器替换占位页：基础属性、已有词条、卡图选择、卡面预览及有序效果组合。
4. 校验通过的 DIY 卡进入图鉴和构筑，所选卡组的精确名单进入新对局；已有对局使用开始时的定义快照。
5. 验证保存重载、拒绝不完整声明、原生部署/指令效果执行、卡组准入以及两个窗口尺寸的界面。

## 本轮创作范围

单位部署完成时的效果、指令打出时的效果；抽牌、获得指挥点/槽数、单位伤害、攻防增益及期限、压制、抑制和行动费修饰。支持本单位、全体友方或全体敌方单位的引擎选靶。资源与抽牌归自己；指令的单位效果须选友方或敌方单位。

单位可编辑兵种、费用、行动费、攻防及闪击、奋战、烟幕、伏击、动员、钳击、重甲、隐蔽；重甲参值 0–3。原生压制模板固定为 1 回合，攻防增益和行动费变化可指定持续、本回合结束或下个己方回合开始。最多 8 条有序效果。

第一版不把任意中文描述当作可执行规则，不开放任意脚本、自由选择目标的指令、总部目标、反制或老兵定义编辑。单位效果监听自己的 `unit.deployed`，表示部署完成后的效果；不冒充原生 `injectDeployKeyword` 的部署前触发及重触发机制。未知声明保留并明确阻止准入。

卡面规则文本由已实现的结构化效果生成，风味文本单独编辑。效果执行、目标合法性、资源和胜负仍归引擎。自定义卡库不修改 21 张原始审核卡的支持清单。未知声明或不能编译/实例化/装载的效果明确拒绝；删除后引用该卡的卡组须由用户修复，不能静默替换卡牌。

## 接入与使用

从上方导航或战场齿轮菜单打开“DIY 卡牌”。新建单位或指令后编辑属性、词条与效果，规则文本自动生成；风味文字单独填写。卡图可借用现有卡牌的插图区域，名称、费用、攻防、兵种与规则全部按当前定义重画，图鉴、构筑与战场保持一致。

“保存”完成原生定义 / DSL / 预制体编译、脚本实例化与单卡数据往返校验，再原子写入 `user://diy-cards.json`。新对局还要检查效果实际装载。Godot 内存加载程序集时，桥接宿主提供当前构建的元数据文件，并将 Roslyn 委托绑定到已经加载的原生程序集，保持原有引用与过滤策略；效果的规则执行仍在引擎。

“用于构筑”保存后打开已有构筑页面并筛选该卡，用户自行加入卡组。“试打”创建临时 12 张卡牌的不限国家卡组，按稀有度加入最多 2 张当前卡，其余使用原始审核卡，走真实洗牌、换牌和对局流程；不保存或激活这副临时卡组。删除卡牌须确认，引用它的已有卡组会明确显示无效，不自动换牌。运行中的对局保留开始时的定义快照。

导出提供 `ORCDIY1:` 卡牌代码及自包含的原生单卡 JSON。卡牌代码可导入本地 UI，导入重新分配 ID，不覆盖原卡；原生 JSON 用于引擎工具，不作为 UI 导入格式。卡库损坏或写入失败时保留原文件和原记录；未知 JSON 字段拒绝。
