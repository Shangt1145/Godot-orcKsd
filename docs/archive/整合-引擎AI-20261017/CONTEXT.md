# 整合上下文：游戏本体 × 引擎架构

本上下文用于「把引擎的 AI/服务层能力接进游戏本体」这一次整合工作。只放术语，不放方案。

## 语言

**引擎谱系**：
同一个引擎仓库里两条互不包含的提交链——本地链（词条程序运行时等）与远端链（Orc.Ai、MCP 服务层）。
_Avoid_: 分支、版本、上游

**游戏本体**：
`OrC-KSD.Godot` UI 仓库。只做呈现与输入，规则归引擎。
_Avoid_: 前端、客户端、Godot 端

**服务层门禁**：
引擎侧 `McpService`——所有动作（人类、AI、agent）进入对局的唯一入口，附带座位过滤投影。
_Avoid_: 桥接、Session、接口层

**对手驱动**：
占一个座位、替 AI 方出牌的那段代码。当前是游戏本体里的 `OrcOpponentDriver`（直调 `Match`），引擎远端提供的是 `Orc.Ai`（走服务层门禁）。
_Avoid_: AI、电脑、机器人（这三个词在本上下文无确定所指）

**整合**：
把两条引擎谱系并成一条，并裁定对手驱动的归属，使游戏本体能同时拿到本地词条能力与远端 AI 能力。
_Avoid_: 合并、同步、升级、rebase（这些是手法，不是目标）

## 待澄清歧义

- 「冲突」：用户口中的冲突可能指①两条谱系分叉 ②对手驱动双实现 ③编译级 API 破坏。当前未裁定。
- 「整合」是否包含「把对手换成引擎 AI」，未裁定。
